Сайт на Flask, который превращает генератор из задания 10.1 в готовый инструмент: пользователь
вводит название компании, выбирает стиль и формат, получает логотип и скачивает его.

Скриншоты (сняты автоматически через браузер без окна):

  с настоящими логотипами.

Готовые логотипы: [results/logos/](results/logos/). Время генерации — 5–10 секунд на штуку.

## Что именно доработано

эксперта:

| Доработка | Что было | Что стало |
|---|---|---|
| **Генерация в отдельном потоке** | браузер ждёт ответа до двух минут, страница выглядит зависшей | страница сразу показывает прогресс, время и число проверок статуса |

| **Форматы** | только квадрат | логотип, иконка, баннер 1280×720, вертикальная обложка 720×1280 — меняется и размер, и текст запроса |

## Как собирается промпт

Из четырёх частей, каждая со своей ролью:

1. **Что рисуем** — зависит от формата: логотип, иконка, баннер или обложка.
2. **Стиль** — один из шести (минимализм, деловой, медтех, технологичный, документ и печать,
   винтаж).
3. **Свободное описание пользователя** — необязательное.
4. **Технический хвост** — плоский знак по центру, белый фон, запрет надписей.

Как это выглядит, показано ниже в разделе про подбор промптов.

## Два найденных и исправленных дефекта

**Первый: блок статуса не скрывался.** При первом же скриншоте обнаружилось, что надпись
«Отправляем запрос…» видна сразу при загрузке страницы. Причина в правилах оформления: у
правила с идентификатором приоритет выше, чем у класса, поэтому `display: flex` перебивало
класс «скрыто». Тесты этого не видели — они проверяют ответы сервера, а не внешний вид.

**Второй: три одновременные генерации ломали галерею.** Нашёлся только на реальном прогоне.
Каждая задача выполняется в своём потоке, и по завершении дописывала файл галереи по схеме
«прочитать целиком → добавить запись → записать целиком». Когда три задачи завершились почти
одновременно, записи наложились друг на друга, файл перестал разбираться, а обработка ошибки
молча возвращала пустой список — галерея просто оказалась пустой, без единого сообщения.

Исправлено тремя изменениями: запись под блокировкой, запись через временный файл с заменой
(чтобы обрыв не оставил половину файла), и сообщение в журнал вместо молчаливого проглатывания
ошибки. Добавлен тест, который запускает двенадцать одновременных записей и проверяет, что
уцелели все.

Оба дефекта — про одно: зелёные тесты не означают, что всё работает. Первый нашёлся, когда я
посмотрел на страницу, второй — когда запустил настоящую генерацию.

## Как подбирались промпты

Приложение склеивает промпт из четырёх частей, и длина каждой оказалась важнее формулировок.
Первая версия описаний стилей была развёрнутой — по строке текста на стиль. Результат: вместо
знаков получались декоративные иллюстрации. После сокращения стилей до двух-трёх признаков
модель стала рисовать именно логотипы.

Пример итогового промпта, который собирает приложение:

> Логотип компании «SINTARIS». медицинский, синий и бирюзовый, чистые линии.
> синий щит с белой галочкой check mark. плоский векторный знак по центру на белом фоне, без текста.

Три правила, которые в итоге работают:

1. **Слово «Логотип» в начале.** Без него модель охотно уходит в иллюстрацию.
2. **Стиль в два-три признака.** Длинное описание размывается.
3. **Запрет надписей в конце.** Иначе модель рисует нечитаемые псевдобуквы.

## Что нужно для запуска

Ключ Yandex Cloud в `.env` в корне репозитория — тот же, что для задания 10.1, требования к
доступу описаны в [результатах 10.1](../Perr10.1/результаты.md).

```powershell
cd Perr10.2
python app.py            # рабочий режим
python app.py --demo     # без ключа, с заглушками
```

Открыть http://127.0.0.1:5000.

**Важно:** приложение использует генератор из задания 10.1, а тот переведён на актуальный API
Yandex AI Studio. Способ из урока перестал работать — разбор причины в
[результатах 10.1](../Perr10.1/результаты.md).
