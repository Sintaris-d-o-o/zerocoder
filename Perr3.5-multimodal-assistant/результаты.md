# Результаты: мультимодальный ассистент «Описание товаров по фото»

Отчёт для сдачи домашнего задания Perr3.5, оформлен по этапам исходного задания.

## Этап 1: Бизнес-задача

Генерация продающих описаний товаров по фото — рутинная задача продавца (интернет-магазин, маркетплейс, объявления), которая обычно отнимает 5–10 минут ручной работы на каждый товар.

**Ассистент принимает на вход:** фото товара и голосовое сообщение (или текст) с деталями от продавца — материал, размер, состояние, цена, особенности.

**Ассистент выдаёт на выход:** текст с готовым продающим описанием товара и голосовое сообщение с озвучкой этого же текста.

## Этап 2: Пайплайн (4 блока)

**Ввод.** Пользователь пишет боту в Telegram: сначала присылает фото товара, затем — голосовое сообщение или текст с деталями.

**Обработка.**
- Распознавание речи (Speech-to-Text, модель OpenAI Whisper) — превращает голосовое сообщение в текст.
- Анализ фото (Vision, модель OpenAI GPT-4o-mini с поддержкой изображений) — «смотрит» на фото и извлекает факты о товаре: что это, цвет, материал, видимое состояние.
- Генерация текста (та же языковая модель) — объединяет факты с фото и детали от продавца, пишет продающее описание.

**Пост-обработка.**
- Финальное оформление ответа (ещё один вызов языковой модели) — собирает структурированный отчёт: готовый текст + ключевые факты + что стоит уточнить.
- Озвучка (Text-to-Speech, модель OpenAI TTS) — превращает готовый текст описания в голосовое сообщение.

**Вывод.** Бот отправляет в Telegram два сообщения: текст с готовым описанием товара и голосовое сообщение с этим же текстом, озвученным вслух.

## Этап 3: Системные промпты

**Промпт для анализа входных данных (фото товара):**
> «Ты — эксперт по описанию товаров для маркетплейса. Внимательно изучи фото товара и перечисли фактами: что это за товар, категория, цвет, материал (если видно), видимое состояние (новое / б/у, есть ли дефекты), заметные особенности. Пиши только то, что реально видно на фото, без домыслов. Формат — короткий список фактов.»

**Промпт для генерации (продающего текста):**
> «На основе фактов о товаре с фото и заметок продавца из голосового сообщения напиши продающее описание товара для интернет-площадки. Стиль — дружелюбный и конкретный, без канцелярита. Структура: заголовок; 3–5 пунктов с ключевыми характеристиками; короткий призыв к действию. Не добавляй факты, которых нет в исходных данных — если чего-то не хватает (например, цены), явно напиши, что это нужно уточнить у продавца.»

**Промпт для последующей обработки (финальный отчёт):**
> «Оформи ответ для продавца в виде короткого структурированного отчёта: 1) Готовое описание товара — то, что можно сразу опубликовать; 2) Ключевые факты, на которых оно основано; 3) Что стоит уточнить или переснять/наговорить заново, если данных не хватило.»

Все три промпта протестированы не только «мысленно», но и реальными вызовами OpenAI API (см. Этап 5) — на тестовом примере (свитер) модель вернула точный, не выдуманный текст на основе входных фактов.

## Этап 4: Реализация бота

Бот реализован на Python с библиотекой `python-telegram-bot`. Он слушает три типа сообщений: фото, голосовые и текстовые. Когда приходит фото, бот сохраняет его в памяти (привязанным к ID пользователя) и просит прислать голосовое сообщение или текст с деталями — специально спроектированной базы данных для этого не нужно, состояние хранится прямо в оперативной памяти процесса. Когда приходит голосовое сообщение, бот скачивает аудиофайл и отправляет его в OpenAI Whisper, чтобы получить текст; если вместо голоса пользователь написал текстом — этот шаг просто пропускается. Дальше бот последовательно делает три обращения к языковой модели OpenAI: сначала анализирует фото и получает список фактов о товаре, затем на основе этих фактов и деталей от продавца генерирует продающий текст, и в конце оформляет всё в структурированный отчёт. Готовый текст описания дополнительно озвучивается через OpenAI TTS, и получившийся аудиофайл отправляется пользователю вторым сообщением. Все секреты — токен Telegram-бота и ключ OpenAI — хранятся только в файле `.env` и загружаются оттуда при старте, нигде в коде не прописаны напрямую. Если на любом из этапов происходит сбой (например, недоступен сервис или сообщение не получилось распознать), пользователю приходит понятное сообщение об ошибке вместо технической тарабарщины, а подробности сбоя пишутся в лог для отладки. Логирование отдельно настроено так, чтобы токен бота не попадал в лог-файлы (стандартные библиотеки по умолчанию пишут в лог полный адрес запроса, включающий токен). В обычных условиях весь пайплайн — от получения голосового сообщения до готового текстового и голосового ответа — занимает несколько секунд.

## Этап 5: Тестирование и анализ

**Автоматические тесты (без обращений к настоящим API — быстро и бесплатно):** 3 юнит-теста на формирование промптов и на логику «жду фото → жду детали» — все прошли успешно (`python -m pytest tests/ -v`).

**Проверка каждого шага пайплайна отдельными вызовами настоящего OpenAI API:**
- Генерация продающего текста и финального отчёта — на примере «шерстяной синий свитер, размер M, почти новый, 1500 рублей» модель вернула точный, аккуратно оформленный текст без выдуманных фактов.
- Озвучка текста (TTS) — получен рабочий аудиофайл.
- Распознавание речи (STT) — тестовый аудиофайл распознан слово в слово.
- Анализ фото (Vision) — модель корректно проанализировала тестовое изображение.

**Реальный тест через Telegram:** бот был запущен и протестирован вживую — пользователь отправил боту голосовое сообщение с деталями товара, бот успешно его распознал и сгенерировал ответ. Текстовое описание было отправлено успешно; при отправке голосового ответа произошёл разовый сетевой таймаут (не ошибка в логике бота, а обрыв сети). Это показало, что вся смысловая часть пайплайна (распознавание речи → анализ фото → генерация текста) работает на реальных данных, а доставка голосового ответа при нестабильной сети иногда может не пройти с первого раза — see раздел «Что улучшить» ниже.

**Что сработало идеально:** распознавание речи, анализ фото, генерация текста без выдуманных фактов, структура ответа — понятная и готовая к публикации.

**Где возникли сложности:** отправка голосового ответа через Telegram может прерываться при нестабильном интернет-соединении (тайм-аут сети, а не ошибка ИИ-моделей).

**Как улучшить:** добавить автоматический повтор отправки при сетевом сбое; для промышленного использования — разместить бота на сервере с постоянным подключением к интернету, а не на локальном компьютере.

**Экономия времени и денег:** ручное составление продающего описания товара занимает 5–10 минут. При 20–30 товарах в месяц это 2–5 часов ручной работы. С ассистентом на подготовку уходит меньше минуты (время на фото и голосовую заметку) — экономия около 2–4 часов в месяц, что при почасовой ставке продавца/контент-менеджера от 500 руб/час даёт ориентировочно 1000–2000 руб. экономии в месяц, не считая более высокого качества и единообразия текстов.
