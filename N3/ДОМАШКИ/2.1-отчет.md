---

## 1. Алгоритм работы сценария

1. Пользователь задаёт параметры: тип ресурса (`todos`, `posts`, `users` или `comments`), `id` нужной записи и `postId` (только для comments).
2. Из типа ресурса автоматически формируется URL: `https://jsonplaceholder.typicode.com/` + resource.
3. HTTP Request отправляет GET-запрос и получает весь список записей.
4. Переключатель проверяет тип ресурса: для `comments` — двойная фильтрация по `id` и `postId`, для остальных — только по `id`.
5. Найденная запись сохраняется в Google Таблицу.

---

## 2. Что было сделано

Я создал автоматизированный сценарий в n8n, который:
- запускается вручную одним нажатием кнопки;
- автоматически формирует URL для запроса к выбранному ресурсу;
- делает HTTP-запрос к публичному API jsonplaceholder.typicode.com;
- фильтрует полученные данные по нужным параметрам;
- сохраняет найденный результат в Google Таблицу.

Все параметры поиска — тип ресурса, id записи и дополнительный фильтр — задаются в одном месте и автоматически подставляются во все последующие шаги через механизм **Expressions** (выражений).

## 3. Нода HTTP Request — настройки

*(см. скриншот «Настройки ноды HTTP Request» в приложении)*

| Поле            | Значение                                    |
|-----------------|---------------------------------------------|
| Метод           | GET                                         |
| URL             | `={{ $json.url }}`  *(Expression)*          |
| Аутентификация  | нет (API открытый)                          |

Ключевой момент — URL задан **не вручную**, а через Expression `={{ $json.url }}`. Это значит, что нода сама берёт адрес из предыдущего шага, где он был сформирован динамически. Если поменять тип ресурса в первой ноде, HTTP-запрос автоматически пойдёт на нужный адрес — без ручного редактирования настроек.

**Адреса API, которые использовались:**
- `https://jsonplaceholder.typicode.com/todos`
- `https://jsonplaceholder.typicode.com/posts`
- `https://jsonplaceholder.typicode.com/users`
- `https://jsonplaceholder.typicode.com/comments`

## 4. Три примера тестирования

### Пример 1 — Список дел (todos), id = 1

**Входные данные (Input):**
```json
{
  "resource": "todos",
  "id": 1
}
```
Нода «Задать параметры» получила: ресурс = `todos`, искомый id = `1`.  
Нода «Сформировать URL» автоматически собрала адрес:  
`https://jsonplaceholder.typicode.com/todos`

HTTP-запрос вернул 200 записей. Нода фильтрации (IF) оставила только ту, где `id` равен `1`.

**Выходные данные (Output):**
```json
{
  "userId": 1,
  "id": 1,
  "title": "delectus aut autem",
  "completed": false
}
```
Результат: найдено дело с id=1, оно **не выполнено** (`completed: false`). Запись добавлена в таблицу.

---

### Пример 2 — Посты (posts), id = 5

**Входные данные (Input):**
```json
{
  "resource": "posts",
  "id": 5
}
```
URL сформировался как `https://jsonplaceholder.typicode.com/posts`.  
После фильтрации осталась одна запись.

**Выходные данные (Output):**
```json
{
  "userId": 1,
  "id": 5,
  "title": "nesciunt quas odio",
  "body": "repudiandae veniam quaerat sunt sed..."
}
```
Результат: найден пост с заголовком «nesciunt quas odio». Запись добавлена в таблицу.

---

### Пример 3 — Комментарии (comments), id = 500, postId = 100

Это самый сложный тест — применяется двойная фильтрация одновременно по двум полям.

**Входные данные (Input):**
```json
{
  "resource": "comments",
  "id": 500,
  "postId": "100"
}
```
URL: `https://jsonplaceholder.typicode.com/comments`.  
API вернул 500 комментариев. Сначала сработал переключатель — он отправил данные по ветке «comments», где фильтр IF проверяет **одновременно два условия**: `id = 500` И `postId = 100`.

**Выходные данные (Output):**
```json
{
  "postId": 100,
  "id": 500,
  "name": "ex eaque eum natus",
  "email": "Emma@joanny.ca",
  "body": "perspiciatis quis doloremque..."
}
```
Результат: из 500 записей найден ровно один комментарий, полностью совпадающий с обоими условиями. Запись добавлена в таблицу.

## 5. Ветвление и фильтрация — бонусная часть

В сценарий добавлены два вида ветвления, что является бонусным заданием.

### Переключатель (Switch) — «Переключатель по URL»

Эта нода работает как развилка на дороге: она смотрит, какой тип ресурса был выбран, и направляет данные по нужному пути.

- Если ресурс = `comments` → данные идут на фильтр с двумя условиями (нужно совпадение и по `id`, и по `postId`)
- Если ресурс = любой другой → данные идут на простой фильтр (только по `id`)

Это важно потому, что у комментариев есть дополнительное поле `postId`, которого нет у постов или дел. Без такого переключателя пришлось бы либо применять ненужный фильтр к todos/posts (где поля postId нет вовсе), либо делать отдельный сценарий для каждого ресурса.

### Фильтр IF — «Отфильтровать по id и postId»

Нода IF (условие) работает как охранник: она проверяет каждую запись из ответа API и пропускает дальше только те, которые совпадают по условию. Остальные просто отбрасываются.

Для comments условие двойное (AND): `id` совпадает **И** `postId` совпадает.  
Для остальных ресурсов — одинарное: только `id` совпадает.

### Что нового я узнал, реализуя ветвление

Самое интересное открытие: n8n не копирует данные в каждую ветку по отдельности — он **передаёт один и тот же поток данных** через переключатель, и каждая ветка получает свои элементы. При этом обе ветки в конце сходились в одну ноду Google Sheets, то есть результат всегда записывался в одно место независимо от того, по какой ветке прошёл запрос.

Ещё одно важное наблюдение: в условиях IF тоже работают Expressions. Правая часть условия `={{ $('Установить тип запроса, id и postId(опционально)').item.json.id }}` берёт значение не из текущей записи, а из другой ноды — той, где были заданы исходные параметры. Это позволяет сравнивать данные из API с параметрами, установленными в самом начале сценария.

## 6. Что такое Expression и почему это удобно

Expression — это способ вставить в любое поле n8n **живое значение** вместо фиксированного текста. Вместо того чтобы писать конкретный URL руками, я пишу `={{ $json.url }}`, и n8n сам подставит туда то, что пришло из предыдущего шага.

В этом сценарии Expressions использовались в нескольких местах:

| Где | Expression | Что делает |
|---|---|---|
| HTTP Request → URL | `={{ $json.url }}` | Берёт URL из предыдущей ноды |
| Set → URL | `=https://jsonplaceholder.typicode.com/{{$json.resource}}` | Собирает URL из базовой части и типа ресурса |
| Switch → условие | `={{ $('Установить...').item.json.resource }}` | Читает тип ресурса из первой ноды |
| IF → левое значение | `={{ $json.id }}` | Берёт id из текущей записи API |
| IF → правое значение | `={{ $('Установить...').item.json.id }}` | Берёт id из параметров запуска |

Главное преимущество: **чтобы изменить параметры поиска, достаточно отредактировать только первую ноду**. Все остальные шаги подхватят изменения автоматически благодаря Expressions.
