# Perr1.4. Мини-среда разработки через CLI и логирование в Python

Оригинал урока: `university.zerocoder.ru`, модуль 1. Текст задания вставлен пользователем в чат.

## Домашнее задание

Реализуй собственную мини-среду разработки через CLI и настрой систему логирования для Python-приложения.

Что нужно сделать:

### 1️⃣ Отработать навигацию и работу с файловой системой

Через CLI-терминал:

- Перейти в директорию home
- Создать папку cli_practice
- Внутри создать структуру:

```
cli_practice/
 ├── app/
 ├── logs/
 └── README.txt
```

- Создать файл main.py внутри папки app
- Создать скрытую папку .config
- Проверить структуру с помощью ls -a и pwd

📌 Важно: все действия выполнить только через терминал.

### 2️⃣ Реализовать Python-скрипт с логированием

В файле main.py:

- Настроить логирование в файл logs/app.log
- Установить уровень логирования INFO
- Настроить формат логов:
  - timestamp
  - level
  - имя модуля
  - сообщение

Внутри скрипта реализовать:

- Лог INFO при запуске приложения
- Лог WARNING (например, при условии x > 100)
- Искусственно сгенерировать ошибку деления на ноль
- Обработать её через try/except
- Записать ошибку через logger.error() или logger.exception()

### 3️⃣ Запуск через виртуальное окружение

Через CLI:

- Создать виртуальное окружение .venv
- Активировать его
- Проверить версию Python
- Запустить main.py
- Деактивировать окружение

### 4️⃣ Проанализировать лог-файл

После запуска:

- Открыть файл logs/app.log
- Найти:
  - timestamp каждой записи
  - уровень логирования
  - сообщение об ошибке
- Кратко описать, в какой последовательности происходили события

## Формат сдачи

Необходимо предоставить:

1️⃣ Скриншоты:

- структуры проекта через ls -R или несколько ls
- запуска скрипта
- содержимого app.log

2️⃣ Краткое описание (5–10 предложений):

- какие уровни логирования использовали;
- чем отличается ERROR от WARNING;
- зачем нужно логирование в файл, если есть вывод в терминал;
- с какими трудностями столкнулись при работе в CLI.
