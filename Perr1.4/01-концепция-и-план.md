# Задание 1.4 — концепция и план

## Что делаем и зачем

Задание учебное и простое по сути: научиться работать с файлами только через
терминал (без проводника и мыши) и научить маленькую программу на Python вести
**журнал событий** (лог) в отдельный файл.

Зачем журнал: вывод в окне терминала исчезает, как только окно закрыли. Файл
журнала остаётся — по нему потом можно понять, что программа делала, когда и где
сломалась. Это то же самое, что бортовой журнал: записи с временем, важностью и
текстом события.

Никаких ключей, API и интернета не нужно — всё делается на этом компьютере.

## Как будет устроено

На компьютере уже есть всё нужное:

- терминал **Git Bash** — в нём работают те же команды, что в задании (`cd`,
  `mkdir`, `touch`, `ls`, `pwd`);
- **Python 3.14** — для скрипта и виртуального окружения.

Проект создаётся там, где требует задание, — в домашней папке пользователя
(`C:\Users\souls\cli_practice`, в терминале это `~/cli_practice`):

```
cli_practice/
 ├── .config/        ← скрытая папка (скрытой её делает точка в начале имени)
 ├── .venv/          ← виртуальное окружение Python
 ├── app/
 │    └── main.py    ← скрипт с логированием
 ├── logs/
 │    └── app.log    ← появится после первого запуска
 └── README.txt
```

**Виртуальное окружение** (`.venv`) — это отдельная «песочница» с собственной
копией Python для проекта. Нужна, чтобы библиотеки одного проекта не мешали
другому. В этом задании библиотеки не ставятся, но порядок «создать → включить →
проверить версию → запустить → выключить» отрабатываем полностью.

### Что делает скрипт main.py

1. Настраивает журнал: файл `logs/app.log`, уровень **INFO** (записываются
   обычные события и всё, что серьёзнее), формат строки:
   `время | уровень | имя модуля | сообщение`.
2. Пишет **INFO** «приложение запущено».
3. Проверяет число `x = 150`; так как оно больше 100, пишет **WARNING**
   («значение выше порога») — это предупреждение: странно, но работа продолжается.
4. Нарочно делит на ноль, перехватывает ошибку (`try/except`) и пишет **ERROR**
   через `logger.exception()` — так в журнал попадает не только текст ошибки, но и
   место в коде, где она случилась.
5. Пишет **INFO** «приложение завершено» — по этой строке видно, что программа
   не упала, а аккуратно справилась с ошибкой и дошла до конца.

Две мелкие, но важные детали:

- путь к `logs/app.log` считается от расположения самого скрипта, а не от того,
  из какой папки его запустили. Иначе запуск из другой папки создал бы журнал
  «не там»;
- файл журнала пишется в кодировке UTF-8, чтобы русский текст в нём читался.

Дополнительно скрипт дублирует сообщения в терминал — так на скриншоте запуска
видно, что происходит, а в файле остаётся постоянная копия. Это заодно наглядно
отвечает на вопрос задания «зачем файл, если есть терминал».

## План реализации

1. **Файловая система (только терминал).** `cd ~` → `mkdir cli_practice` →
   `mkdir app logs .config` → `touch README.txt app/main.py` → проверка `pwd`,
   `ls -a`, `ls -R`.
2. **Скрипт.** Записать код в `app/main.py` (текст скрипта сохраняется и в папку
   задания в репозитории).
3. **Виртуальное окружение.** `python -m venv .venv` →
   `source .venv/Scripts/activate` (на Windows путь `Scripts`, а не `bin`, как в
   Linux/Mac — это отметим как трудность) → `python --version` →
   `python app/main.py` → `deactivate`.
4. **Анализ журнала.** `cat logs/app.log`, разобрать каждую строку: время,
   уровень, сообщение, порядок событий.
5. **Скриншоты** — см. ниже.
6. **Краткое описание** (5–10 предложений) и `результаты.md`.

## Скриншоты — нужно ваше решение

Задание требует три скриншота: структура проекта, запуск скрипта, содержимое
`app.log`. Я работаю в терминале, но не могу сфотографировать ваш экран. Два
варианта:

- **А (рекомендую).** Я выполняю все команды сам и сохраняю их полный вывод. Из
  этого настоящего вывода делаю картинки в виде окна терминала (через браузер Edge,
  этот приём уже работал в задании 10.2). Плюс кладу в папку пошаговую шпаргалку
  команд — если захотите, повторите их сами за 5 минут и снимете «живые» скриншоты.
- **Б.** Я готовлю шпаргалку и код, а все команды и скриншоты делаете вы, затем
  кладёте картинки в папку — я проверю и допишу отчёт.

## План тестирования

- После создания структуры — `ls -a` и `ls -R` показывают все папки и файлы,
  включая скрытую `.config`.
- После запуска — в `logs/app.log` ровно четыре записи в правильном порядке:
  INFO (запуск) → WARNING (x > 100) → ERROR (деление на ноль, с местом ошибки) →
  INFO (завершение).
- Проверить, что каждая строка содержит время, уровень, имя модуля и сообщение.
- Запустить скрипт из **другой** папки и убедиться, что журнал всё равно пишется
  в `cli_practice/logs/app.log`.
- `python --version` внутри окружения показывает Python из `.venv`
  (проверка через `which python`).

## План демонстрации

В папке задания `Perr1.4/` в репозитории будут лежать:

- `main.py` — копия скрипта;
- `app.log` — настоящий журнал после запуска;
- `терминал-протокол.txt` — полный текст всех команд и их вывода по порядку;
- `шпаргалка-команд.md` — команды для самостоятельного повтора;
- `screenshots/` — три скриншота;
- `demo.md` — как показать проверяющему;
- `результаты.md` — что сделано, краткое описание 5–10 предложений и сверка
  с заданием.

Проверяющему отправляются три скриншота, краткое описание и, при желании, ссылка
на папку в репозитории.
