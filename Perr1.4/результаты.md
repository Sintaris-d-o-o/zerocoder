# Задание 1.4 — что сделано и что получилось

## Коротко

В домашней папке через терминал Git Bash создан проект `~/cli_practice` с
папками `app`, `logs`, скрытой `.config` и файлом `README.txt`. Скрипт
`app/main.py` ведёт журнал в `logs/app.log`. Запуск выполнен из виртуального
окружения `.venv`. Журнал содержит четыре записи в правильном порядке, ошибка
деления на ноль перехвачена и записана вместе с местом в коде, где она произошла.

## Краткое описание (для отправки)

Использовано три уровня логирования: **INFO** для обычных событий (запуск и
завершение программы), **WARNING** для подозрительной ситуации (x = 150 больше
порога 100) и **ERROR** для ошибки деления на ноль. WARNING означает «что-то не
так, но работа идёт дальше», а ERROR — «операция не выполнилась»: деление не
дало результата, и через `logger.exception()` в журнал попал полный след ошибки с
номером строки. Журнал в файле нужен, потому что вывод терминала исчезает при
закрытии окна, а файл хранит историю всех запусков: по нему можно разобраться в
сбое, который произошёл ночью или у другого человека, и искать нужное командой
`grep`. Это проявилось и на практике: при первом запуске вывод в терминал сломался
на русском тексте, а файл журнала всё равно записался полностью и правильно.
Главная трудность в CLI — особенности Windows: при передаче вывода по конвейеру
Python выводил текст в кодировке cp1252 без кириллицы, и пришлось явно включить
UTF-8 в скрипте. Вторая особенность — окружение на Windows включается командой
`source .venv/Scripts/activate`, а не `.venv/bin/activate`, как в инструкциях для
Linux и Mac. Третья: команда `ls` без ключа `-a` не показывает скрытую папку
`.config`, и легко решить, что она не создалась.
