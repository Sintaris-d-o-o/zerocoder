# Инструменты для локального развёртывания моделей: сравнительная таблица

**Задание 9.2, пункт 2.** В таблицу включены все инструменты из урока, а также четыре, которых
в уроке нет, но которые сегодня стали стандартом (Ollama, vLLM, LM Studio, text-generation-webui).
Последняя колонка показывает, что из этого реально работает в **Taris для сертификатов**
(`certtaris`) — ассистенте по регламентам медизделий, развёрнутом на рабочей станции SintAItion.

## Как выбрать: три типичные ситуации

**Один человек на своём ноутбуке, надо просто попробовать модель.**
KoboldCpp или LM Studio — скачал файл, выбрал модель, работает. Программировать не нужно.
Если хочется командной строки и максимальной экономии памяти — llama.cpp.

**Небольшая команда, своя модель внутри приложения (наш случай).**
Ollama плюс Docker. Ollama даёт локальный сервер с привычным API, Docker изолирует сервисы друг
от друга. Поиск по документам — на эмбеддингах (sentence-transformers), а не на большой модели:
это в разы дешевле и быстрее. Векторы удобно хранить в pgvector, если PostgreSQL уже есть.
Дообучение — через Hugging Face Transformers на арендованной видеокарте, результат выгружается
в GGUF и возвращается в Ollama.

**Продакшн на десятки одновременных пользователей.**
vLLM на серверной видеокарте. Ollama обслуживает запросы по очереди, и при нагрузке очередь
становится узким местом; vLLM специально сделан для параллельных запросов.

## Как эти инструменты сочетаются в Taris для сертификатов

Полный путь от обучения до ответа пользователю:

1. **Дообучение** — Hugging Face Transformers, метод QLoRA, на арендованной видеокарте L4
   (задание 8.1): 3 545 обучающих примеров, 444 шага, два часа.
2. **Выгрузка** — модель переводится в формат GGUF с квантизацией Q4_K_M: **3,43 ГБ** вместо
   9,5 ГиБ в исходной точности.
3. **Запуск** — Ollama на рабочей станции SintAItion, внутри неё работает llama.cpp, вычисления
   идут на встроенной графике AMD через ROCm.
4. **Поиск по нормам** — эмбеддинги MiniLM превращают вопрос в вектор, PostgreSQL с pgvector
   ищет похожие фрагменты среди 14 947, результаты объединяются с полнотекстовым поиском.
   Большая модель на этом этапе не используется вовсе.
5. **Изоляция** — часть сервисов в контейнерах Docker, часть работает напрямую.
6. **Маршрутизация запросов** — мультимодельный агент из задания 9.1 решает, какой вопрос
   дешёвой модели, а какой мощной.

## Что показал наш собственный опыт

- **Эмбеддинги действительно заменяют большую модель там, где не нужна генерация.** Поиск
  нужного фрагмента среди 14 947 занимает в среднем 1,2 миллисекунды и делается моделью в сорок
  раз меньше языковой. На саму языковую модель приходится 92 % времени ответа — оптимизировать
  имеет смысл только её.
- **Локальная модель без базы знаний ошибается в фактах.** В задании 9.1 Gemma 4, отвечая по
  памяти, назвала неверный надзорный орган и заявила, что у сертификата нет предельного срока
  действия, хотя статья 56 MDR устанавливает пять лет. С подключённым поиском по нормам таких
  ошибок нет — модель цитирует источник.
- **Реранкер стоит своей цены.** На контрольном наборе из 17 вопросов он поднял результат с
  13 успешных до 15 и убрал единственный провал. Платить приходится гигабайтом памяти и
  удвоением времени поиска, но поиск и так занимает миллисекунды.
- **Потеря видеокарты замедляет не так сильно, как кажется.** Тот же запрос на встроенной
  графике — 22,5 секунды, на 24 потоках процессора — 41,3 секунды. Это в 1,8 раза, а не в пять.
  Но чтение длинного запроса проседает в семь раз, и для ассистента с базой норм это главный
  удар: в запросе всегда лежат найденные фрагменты регламентов.
- **Ollama обрабатывает запросы по очереди.** Пока отвечают один-два человека, это незаметно;
  при десятке одновременных пользователей понадобится vLLM и серверная видеокарта.
- **Docker избавляет от конфликтов версий**, но на процессорах архитектуры ARM часть готовых
  образов приходится собирать самостоятельно.

## Выводы

1. **Универсального инструмента нет** — есть три разных сценария: попробовать, встроить в своё
   приложение, выдержать нагрузку. Для каждого свой набор.
2. **llama.cpp лежит в основе почти всего простого** — Ollama, KoboldCpp и LM Studio являются
   надстройками над ним. Выбор между ними — это выбор удобства, а не движка.
3. **Эмбеддинги — самый недооценённый инструмент.** Задачи поиска, классификации и сравнения
   текстов решаются моделью в сорок раз меньше языковой и занимают миллисекунды против секунд.
4. **Docker нужен всегда, как только сервисов больше одного.**
5. **Автономные агенты пока не для продакшна**: в области, где ошибка означает неверную
   рекомендацию по регламенту, непредсказуемость недопустима.
6. **Наш набор закрывает задачу целиком** и состоит только из бесплатных инструментов:
   Transformers для дообучения, Ollama и llama.cpp для запуска, sentence-transformers и
   pgvector для поиска, bge-reranker для точности, Docker для изоляции. Платный внешний сервис
   остаётся только как запасной вариант.
