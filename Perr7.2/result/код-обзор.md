# Обзор кода: какой пункт задания где реализован

Все файлы лежат в папке `код/` целиком — это точные копии того, что работает на сервере.
Номера строк указаны по этим копиям.

## 1. Генерация текста поста

Была в продукте до этого задания и не переписывалась.

| Что | Где |
|---|---|
| Генерация плана/поста (веб) | `bot_web.py` → `_generate_content()` — сначала пробует сценарий N8N, иначе локальная модель |
| Генерация плана/поста (Telegram) | `bot_content.py` → `_generate_content_with_llm()` (строка 89) и `_do_generate_plan()` / `_do_generate_post()` |
| Правка поста своими словами | `bot_content.py` → шаг `correcting_post` в `handle_message()` |

Провайдер модели выбирается настройкой `LLM_PROVIDER`: на боевом сервере это локальная
Ollama, `openai` — рабочая альтернатива, требуемая заданием.

## 2. Генерация изображения — `код/bot_images.py`

| Функция | Строка | Что делает | Соответствие примеру преподавателя |
|---|---|---|---|
| `describe_image_for_post()` | 256 | Языковая модель описывает **сцену** поста; тема дописывается в конец программно | `PostGenerator.generate_post_image_description()` |
| `generate_image()` | 137 | Запрос к OpenAI Images (`gpt-image-1` / `dall-e-3`), проверка ответа, сохранение файла | `ImageGenerator.generate_image()` |
| `_store()` | 126 | Пишет байты в `CONTENT_MEDIA_DIR/<пользователь>/<id>.png` | в примере изображение не сохранялось — оставалась ссылка |
| `image_path()` | 94 | Единственный способ превратить путь из базы в путь на диске; всё, что не `<число>/<hex>.png`, отвергается | защита от выхода за пределы папки |
| `is_configured()` | 57 | Если провайдер выключен или ключа нет — кнопки генерации в интерфейсе просто нет | — |

Особенности, которых нет в примере:

* **Ответ, а не исключение.** `generate_image()` всегда возвращает словарь
  `{"ok": …, "error": …}`. Её вызывают из обработчика кнопки Telegram и из веб-маршрута:
  исключение там — это «кнопка ничего не делает» и «страница 500».
* **Оба формата ответа.** `gpt-image-1` отвечает base64, `dall-e-3` — ссылкой; у ссылки
  запрашивается `b64_json`, а если провайдер всё же вернул URL, байты скачиваются.
* **Тема дописывается к описанию.** См. раздел «Найденный дефект» в `результаты.md`.

## 3. Учёт постов и показателей — `код/store_content.py`

| Функция | Строка | Что делает |
|---|---|---|
| `save_post()` | 183 | Строка в `content_posts`: тема, площадка, текст, путь к картинке, статус |
| `record_metrics()` | 307 | **Добавляет** наблюдение в `content_metrics` (лайки, просмотры, репосты, комментарии, подписчики, источник) |
| `engagement()` | 298 | (лайки + репосты + комментарии) ÷ просмотры × 100, одна десятая |
| `stats_summary()` | 365 | Всё, что печатает дашборд: итоги, средняя вовлечённость, темы, площадки, помесячный ряд |
| `latest_metrics()` | 337 | Самое свежее наблюдение по каждому посту — одним запросом |
| `mark_published()` | 279 | Пост становится опубликованным, запоминаются канал и ссылка |

Схема описана один раз для PostgreSQL, для SQLite получается автоматической заменой типов
(строка 138) — так две базы не могут разойтись.

## 4. Публикация и статистика ВКонтакте — `код/bot_content_vk.py`

| Функция | Строка | Соответствие примеру |
|---|---|---|
| `upload_photo()` | 76 | `VKPublisher.upload_photo()` |
| `publish()` | 102 | `VKPublisher.publish_post()` |
| `fetch_post_stats()` | 142 | `VKStats.get_stats()` |
| `fetch_followers()` | 165 | `VKStats.get_followers()` |
| `sync_metrics()` | 182 | новое: обновляет показатели всех опубликованных постов за один заход |

Отличия от примера: токен и ID сообщества берутся **из настроек пользователя**, а не из
файла конфигурации; сбой загрузки картинки не отменяет публикацию текста; число
подписчиков запрашивается один раз на весь заход, а не по разу на пост.

| Маршрут | Назначение |
|---|---|
| `GET /agents/content` | форма ввода темы |
| `POST /agents/content/plan` | контент-план |

Шаблон дашборда — `код/agents_content_stats.html`: карточки (строки 28–43), столбчатая
диаграмма на чистом CSS без внешних библиотек (46–63), популярные темы (67–80), таблица с
редактируемыми показателями (84–147).

## 6a. Какая площадка публикуема — `код/bot_content.py`

`PUBLISHABLE_PLATFORMS = ("telegram", "vk")` и функции `can_publish_to()` /
`platform_label()`. Площадка, выбранная в начале, определяет, как пост **написан**,
а не куда его можно **отправить**: принять пост от бота могут только Telegram-канал
и сообщество ВКонтакте. Для остальных площадок страница объясняет это и предлагает
скачать текст и картинку; в Telegram то же пояснение выводится перед списком
каналов (`_ask_publish_confirm()`).

## 7. Настройки (ключи — только из окружения)

```ini
CONTENT_IMAGE_PROVIDER=openai      # openai | off
CONTENT_IMAGE_MODEL=gpt-image-1    # или dall-e-3
CONTENT_IMAGE_SIZE=1024x1024
CONTENT_MEDIA_DIR=<домашняя-папка>/content_media
CONTENT_VK_ENABLED=1
CONTENT_VK_API_VERSION=5.236
```

Ключ OpenAI отдельной переменной для картинок **нет** намеренно: используется тот же
`OPENAI_API_KEY`, что и для текста, — иначе при смене ключа где-то остаётся старая копия.
