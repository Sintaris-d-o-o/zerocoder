# Концепция и план: Perr7.2 — SMM-эксперт с ИИ (часть 1)

## Тема

**Путешествия и уютные маршруты по Европе.** Аудитория — самостоятельные путешественники
30–45 лет. Цель публикаций — подписки и брони авторских туров.

## Главное решение: расширяем работающий продукт, а не пишем скрипт

У преподавателя пример собран как отдельное приложение: `generators/`, `social_publishers/`,
`social_stats/`, `config.py` и `test.py`, который всё это связывает. Логика правильная, и
именно она перенесена — но перенесена **в архитектуру Taris**, действующего ассистента с
Telegram-ботом и веб-интерфейсом, где «Контент-стратег» уже существовал и умел писать
контент-планы и посты.

Так задание получает то, чего у отдельного скрипта быть не может: авторизация,
многопользовательский режим, база данных, четыре языка интерфейса, тесты и боевое
развёртывание. А проверить его можно по ссылке, а не «запустите у себя».

| Пример преподавателя | Что соответствует в Taris | Почему так |
|---|---|---|
| `config.py` с ключами прямо в файле | переменные окружения + хранилище ключей, токены ВКонтакте — отдельно для каждого пользователя | ключ в коде утекает в первый же репозиторий; одно сообщество принадлежит одному человеку, а не серверу |
| `generators/text_gen.py` → `PostGenerator` | `_generate_content()` / `_generate_content_with_llm()` | генерация уже была; добавлять второй генератор текста незачем |
| `generators/image_gen.py` → `ImageGenerator` | **`core/bot_images.py`** (новый модуль) | сделан как «сервис» уровня ядра, по образцу модуля LLM: один вход, выбор провайдера внутри |
| `social_publishers/vk_publisher.py` | **`features/bot_content_vk.py`** (новый модуль) | публикация в сообщество ВКонтакте + вложение картинки |
| `social_stats/vk_stats.py` | он же: `fetch_post_stats()`, `fetch_followers()`, `sync_metrics()` | статистика и публикация — работа с одним и тем же API, разделять их на два модуля незачем |
| `posts = [...]` — список в памяти | **`core/store_content.py`**: таблицы `content_posts` + `content_metrics` | список в памяти исчезает при перезапуске; статистика — это то, что должно пережить перезапуск |
| `test.py` — ручной запуск | 52 автоматических теста + развёртывание | «запустил и посмотрел» не масштабируется на два интерфейса и четыре языка |

## Как устроен процесс

```
   тема / аудитория / цель
              │
              ▼
      контент-план (7 постов)  ──► выбрать пост №N
              │                          │
              ▼                          ▼
        быстрый пост            готовый текст поста
                                         │
                        ┌────────────────┴────────────────┐
                        ▼                                 ▼
             ИИ пишет ОПИСАНИЕ СЦЕНЫ            «Сохранить черновик»
                        │                                 │
                        ▼                                 ▼
              модель рисует картинку            content_posts (учёт)
                        │                                 │
                        └──────────► публикация ──────────┘
                                   Telegram / ВКонтакте
                                            │
                                            ▼
                                   content_metrics (наблюдения)
                                            │
                                            ▼
                                 📊 статистика публикаций
```

### Почему две ступени при генерации картинки

Если отдать модели изображений сам пост, она нарисует картинку, набитую нечитаемыми
буквами, — она честно пытается изобразить текст. Поэтому сначала языковая модель
описывает **сцену** («узкая улочка старого города на закате, лаванда в горшках, тёплый
свет»), и уже это описание идёт в модель изображений. Ровно так же устроено у
преподавателя (`generate_post_image_description` → `generate_image`).

### Почему картинка — файл, а не ссылка

DALL·E возвращает ссылку, которая перестаёт открываться примерно через час. Пост,
сохранённый в понедельник, во вторник показывал бы пустую рамку. Поэтому байты
скачиваются сразу и лежат файлом на сервере; в базе хранится только относительный путь.

### Почему показатели — история, а не колонки

`content_metrics` — это временной ряд: каждое обновление добавляет строку с датой.
Затирать предыдущее значение означало бы уничтожать историю, из которой строится
диаграмма по месяцам. Вовлечённость при этом не хранится вообще: она вычисляется при
чтении, поэтому не может разойтись с лайками и просмотрами, которые печатаются рядом.
