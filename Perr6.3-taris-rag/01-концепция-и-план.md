# Концепция и план — Perr6.3: векторная база знаний агента-нутрициолога Taris

## Что делаем и зачем

В задании 6.2 мы разобрали готовый пример бота, который отвечает на вопросы по базе знаний
(«найди, потом ответь» — технология **RAG**), и наметили, как применить его в Taris.

У нас такая база уже есть: **агент-нутрициолог Taris** (проект `sintaris-pl`) отвечает на
вопросы о питании и продукции LR по своей базе знаний. Поэтому в этом задании не изобретаем
всё с нуля, а **берём проверенный код Taris** и собираем из него компактную учебную версию,
которая наглядно показывает три шага задания: векторная база → чанки и векторы → ответы.

## Что берём из Taris (копируем в папку задания)

| Что | Откуда в Taris | Зачем |
|---|---|---|
| Разбиение на чанки | `src/core/chunking.py` (`_chunk_text`) | «Умный» чанкер Taris: режет текст по разделам (кусок не перескакивает через заголовок) и к каждому куску дописывает путь заголовков «документ → глава → раздел», чтобы кусок не терял смысл в отрыве от контекста |
| Модель векторов | `src/core/bot_config.py` (`EMBED_MODEL`) | `paraphrase-multilingual-MiniLM-L12-v2` — бесплатная, понимает русский, вектор из 384 чисел, уже скачана на компьютер |
| Векторная база | `src/core/store_sqlite.py` (таблица `vec_embeddings`, `search_similar`) | **sqlite-vec** — векторный поиск прямо внутри файла SQLite. Та же схема таблицы, что в Taris |
| Тексты базы | `doc/kb-corpora/nutri/` | Справочник LR_OK, рецепты, статьи: клетчатка, ощелачивание, меню и нутрицевтики, циркадные ритмы |

Код и тексты копируются в репозиторий zerocoder (так решил пользователь, хотя этот репозиторий
публичный на GitHub, а `sintaris-pl` — приватный). Файл «О Виктории + ПРОМТ» не берём —
это промпт и личные данные, к базе знаний он не относится.

Сам Taris-чанкер зависит от общего конфига бота; при копировании заменяю эту зависимость
двумя константами (размер чанка 512 символов и нахлёст, как в Taris). Логику не меняю.

## Как это будет работать

1. **Загрузка текстов** — txt и docx из `data/`.
2. **Чанки** — чанкер Taris режет каждый документ на кусочки ≈512 символов.
3. **Векторы** — модель превращает каждый кусочек в «отпечаток смысла» из 384 чисел.
4. **Векторная база** — отпечатки и тексты сохраняются в файл `kb.sqlite` (sqlite-vec).
   База каждый раз строится заново, чтобы не копились дубли (урок из 6.5).
5. **Ответ на вопрос** — вопрос тоже превращается в вектор, база находит 5 ближайших по
   смыслу кусочков, и локальная модель **llama3.2:3b** (Ollama) отвечает по-русски только по
   ним, с указанием источников. Если ответа в базе нет — честно об этом говорит. Ограничиваю
   длину ответа и ставлю штраф за повторы, чтобы маленькая модель не зацикливалась (урок из 6.5).

Всё работает локально, без интернета и без ключей API.

## План реализации

1. Скопировать подборку текстов в `data/`, чанкер Taris — в `taris_chunking.py`.
2. `build_index.py` — тексты → чанки → векторы → `kb.sqlite`; печатает статистику.
3. `ask.py` — вопрос → поиск → ответ с источниками (один вопрос или диалог).
4. Установить пакет `sqlite-vec` (единственного не хватает).

## План тестирования

- База построилась: сколько чанков из каждого файла, длина вектора 384.
- Поиск отдельно от модели: для 5–6 вопросов смотрю, какие кусочки нашлись и подходят ли они.
- Полный цикл, ответы читаю целиком:
  - вопросы, ответ на которые есть в базе (например, «зачем нужна клетчатка?», «что такое
    Алоэ Вера Гель от LR и как его принимать?», рецепт);
  - вопрос «другими словами» — поиск должен идти по смыслу, а не по совпадению слов;
  - вопрос не по теме («какая погода в Белграде?») — бот должен отказаться.
- Результаты — в `tests/test-results.md`.

## План демонстрации

- `demo.md`: две команды — построить базу и задать вопрос.
- Скриншоты кода для отчёта в `screenshots/`: чанкинг и векторы, создание базы, поиск и
  генерация ответа, пример работы в терминале.
- `результаты.md` — краткий отчёт для преподавателя и сверка с заданием.

## Какие доступы нужны

Никаких: всё локально (Ollama с llama3.2:3b и Python-библиотеки уже установлены, доставлю
только `sqlite-vec`).
