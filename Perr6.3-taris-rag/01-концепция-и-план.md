# Концепция и план — Perr6.3: векторная база знаний агента-нутрициолога Taris

## Что делаем и зачем

В задании 6.2 мы разобрали готовый пример бота, который отвечает на вопросы по базе знаний.
Это технология **RAG** («найди, потом ответь»). Там же мы наметили, как применить её в Taris.

У нас такая база уже есть: **агент-нутрициолог Taris** отвечает на вопросы о питании и
продукции LR по своей базе знаний. Поэтому в этом задании мы не изобретаем всё с нуля, а
**берём проверенный код Taris**. Из него собираем компактную учебную версию, которая наглядно
показывает три шага задания: векторная база → чанки и векторы → ответы.

## Конфиденциальность: код Taris не публикуется

Репозиторий zerocoder публичный на GitHub, а Taris — коммерческий и приватный. Поэтому всё,
что взято из Taris, лежит **только на вашем компьютере**, в папке `Perr6.3-taris-rag/private/`.
Эта папка исключена из git (`.gitignore`) и никогда не попадает на GitHub. В ней лежат:

- `private/code/` — рабочий код задания: чанкер Taris, построение базы, ответы на вопросы;
- `private/data/` — тексты нутрициолога;
- `private/kb.sqlite` — сама векторная база;
- `private/screenshots/` — скриншоты кода и работы для отчёта. Вы прикладываете их к ответу
  преподавателю вручную. На GitHub они тоже не попадают;
- `private/test-results.md` — подробные результаты тестов с цитатами из базы.

На GitHub уходят только общие документы:
- задание;
- эта концепция;
- инструкция по запуску;
- отчёт простыми словами со сверкой с заданием.

Ни кода Taris, ни текстов справочника, ни скриншотов там нет. Перед каждым коммитом проверяю
`git status`, что из `private/` ничего не попало в индекс.

## Что берём из Taris

| Что | Зачем |
|---|---|
| Модуль разбиения на чанки | «Умный» чанкер Taris режет текст по разделам: кусок никогда не перескакивает через заголовок. К каждому куску он дописывает путь заголовков «документ → глава → раздел», чтобы кусок не терял смысл в отрыве от контекста |
| Модель векторов | `paraphrase-multilingual-MiniLM-L12-v2` — бесплатная, понимает русский. Каждый кусок превращается в вектор из 384 чисел. Модель уже скачана на компьютер |
| Векторная база | **sqlite-vec** — векторный поиск прямо внутри файла SQLite. Схема таблицы та же, что в Taris |
| Тексты базы | Подборка из базы нутрициолога: справочник LR_OK, рецепты и статьи — клетчатка, ощелачивание, меню и нутрицевтики, циркадные ритмы |

Файл «О Виктории + ПРОМТ» в базу не берём: это промпт и личные данные, а не база знаний.

Чанкер Taris берёт свои настройки из общего конфига бота. В рабочей копии эта зависимость
заменена двумя константами: размер чанка 512 символов и нахлёст, как в Taris. Логика чанкера
не меняется.

## Как это будет работать

1. **Загрузка текстов** — файлы txt и docx из `private/data/`.
2. **Чанки** — чанкер Taris режет каждый документ на кусочки примерно по 512 символов.
3. **Векторы** — модель превращает каждый кусочек в «отпечаток смысла» из 384 чисел.
4. **Векторная база** — отпечатки и тексты сохраняются в файл `private/kb.sqlite`. База
   каждый раз строится заново, чтобы не копились дубли (урок из 6.5).
5. **Ответ на вопрос** — работает так:
   - вопрос тоже превращается в вектор;
   - база находит 5 ближайших по смыслу кусочков;
   - локальная модель **llama3.2:3b** (через Ollama) отвечает по-русски только по ним и
     указывает источники;
   - если ответа в базе нет, бот честно об этом говорит.

   Длину ответа ограничиваю и ставлю штраф за повторы, чтобы маленькая модель не
   зацикливалась (урок из 6.5).

Всё работает локально, без интернета и без ключей API.

## План реализации

1. Создать `private/` и исключить её из git.
2. Скопировать туда подборку текстов и чанкер Taris.
3. Написать `build_index.py`: тексты → чанки → векторы → `kb.sqlite`. Скрипт печатает
   статистику построения.
4. Написать `ask.py`: вопрос → поиск → ответ с источниками. Работает в двух режимах — один
   вопрос или диалог.
5. Установить пакет `sqlite-vec` — это единственное, чего не хватает.

## План тестирования

- **База построилась.** Сколько чанков получилось из каждого файла; длина вектора — 384.
- **Поиск отдельно от модели.** Для 5–6 вопросов смотрю, какие кусочки нашлись и подходят ли они.
- **Полный цикл.** Ответы читаю целиком. Проверяю три вида вопросов:
  - вопросы, ответ на которые есть в базе;
  - вопрос «другими словами» — поиск должен идти по смыслу, а не по совпадению слов;
  - вопрос не по теме («какая погода в Белграде?») — бот должен отказаться отвечать.
- **Результаты.** Подробные — в `private/test-results.md`. В публичный отчёт — только краткий
  итог без цитат справочника.

## План демонстрации

- **`demo.md`** — две команды: построить базу и задать вопрос. Запуск — на вашем компьютере.
- **Скриншоты** для отчёта — в `private/screenshots/`, только локально:
  - разбиение на чанки и векторизация;
  - создание векторной базы;
  - поиск и генерация ответа;
  - пример работы в терминале.
- **`результаты.md`** — краткий отчёт и сверка с заданием.

## Какие доступы нужны

Никаких: всё работает локально. Ollama с llama3.2:3b и Python-библиотеки уже установлены,
доставлю только `sqlite-vec`.
