# Концепция и план — Perr6.3: векторная база знаний для онбординг-бота Тариса

## Что делаем и зачем

В задании 6.2 мы разобрали готовый пример «бота-помощника для новичков» и придумали, как
применить его в Тарисе: новый эксперт или студент задаёт вопрос («как загрузить видео урока?»,
«когда приходят выплаты?») и сразу получает ответ из базы знаний платформы, а не ждёт куратора.

В этом задании собираем **первую рабочую версию** такого бота (в 6.2 она называлась «Версия 1 —
простой RAG»). RAG — это «найди, потом ответь»: сначала бот ищет в базе знаний подходящие по
смыслу кусочки текста, а потом языковая модель формулирует ответ **только на их основе**, а не
придумывает от себя.

## Как это будет работать

1. **Текст базы знаний.** Готовлю небольшую базу знаний Тариса — несколько текстовых файлов:
   правила платформы, инструкция для эксперта (как создать курс, загрузить материалы, настроить
   выплаты), FAQ для студентов (доступ к урокам, сертификаты, возвраты). Текст — учебный,
   составленный по описанию проекта Тарис.
2. **Разбиение на чанки.** Длинный текст режется на кусочки примерно по абзацу (≈500 символов,
   с небольшим «нахлёстом» соседних кусочков, чтобы мысль на стыке не потерялась). Зачем: искать
   нужно конкретное место в документе, а не весь документ целиком.
3. **Векторные представления.** Каждый кусочек превращается в набор чисел — «отпечаток смысла»
   (embedding). Похожие по смыслу тексты дают похожие отпечатки, даже если слова разные
   («оплата» ↔ «выплаты»). Считает их бесплатная модель `paraphrase-multilingual-MiniLM-L12-v2`,
   которая понимает русский и уже скачана на ваш компьютер.
4. **Векторная база данных.** Отпечатки вместе с текстом сохраняются в **ChromaDB** — ту же
   базу, что в разобранном примере из 6.2. База хранится в папке на диске: построили один раз —
   дальше пользуемся.
5. **Генерация ответа.** На вопрос пользователя база находит 4 самых близких по смыслу кусочка,
   они вместе с вопросом передаются локальной модели **llama3.2:3b** (через Ollama, уже
   установлена). Модель отвечает по-русски и только по найденному тексту; если ответа в базе нет —
   честно говорит «не знаю, обратитесь в поддержку». В конце ответа показываются источники
   (из какого файла взят фрагмент).

Всё работает на вашем компьютере, без интернета и без платных API — ключи не нужны.

## План реализации

1. Написать базу знаний Тариса (`data/*.md`, 3–4 файла).
2. `build_index.py` — загрузка файлов → разбиение на чанки → векторы → сохранение в ChromaDB
   (база каждый раз пересоздаётся с нуля, чтобы не копились дубли — урок из 6.5).
3. `ask.py` — вопрос → поиск в базе → ответ модели с источниками. Режим одного вопроса и
   режим диалога.
4. Настройки модели с защитой от «зацикливания» (ограничение длины ответа, штраф за повторы —
   урок из 6.5).

## План тестирования

- Проверить, что база построилась: сколько чанков, размеры, пример одного вектора (длина 384).
- Проверить поиск отдельно от модели: для 5–6 контрольных вопросов посмотреть, какие кусочки
  нашлись и правильные ли они.
- Прогнать вопросы через полный цикл и прочитать ответы целиком:
  - вопросы, ответ на которые есть в базе («как настроить выплаты?», «можно ли вернуть деньги
    за курс?»);
  - вопрос «другими словами» (проверка, что поиск идёт по смыслу, а не по словам);
  - вопрос, которого в базе нет («какая погода в Белграде?») — бот должен отказаться отвечать.
- Результаты сохранить в `tests/test-results.md`.

## План демонстрации

- `demo.md`: две команды — построить базу и задать вопрос.
- Скриншоты кода (для отчёта): разбиение на чанки и векторизация, создание векторной базы,
  поиск и генерация ответа, пример работы в терминале — в папке `screenshots/`.
- `результаты.md` — краткий отчёт для преподавателя и сверка с заданием.

## Какие доступы нужны

Никаких — всё локально. Нужны только уже установленные Ollama (модель llama3.2:3b) и
Python-библиотеки (langchain, chromadb, sentence-transformers — уже стоят).
