# Концепция и план — Perr7.4: поисковик по смыслу на технологиях Taris

## Что делаем и зачем

Оригинальное задание (`00-задание7.4.md`) — сделать в Google Colab поисковик, который по
описанию вакансии находит подходящие резюме, с помощью эмбеддингов (числовых «отпечатков
смысла» текста) и векторной базы данных.

По вашей просьбе меняем две вещи:

1. **Данные** — не резюме (нет ни файла с резюме, ни разрешения использовать чужие личные
   данные), а тема **нутрициологии/здоровья** — та же область, в которой вы реально работаете
   (курс нутрициолога, детокс-протоколы, БАДы). Вместо «вакансия → резюме» будет «вопрос
   пользователя о здоровье/питании → подходящие материалы базы знаний» — по смыслу то же самое
   задание (поиск по смыслу среди множества документов), просто на вашей предметной области.
2. **Платформа** — не Google Colab и не случайный набор библиотек из урока (LangChain, Chroma
   и т.п.), а **то же самое, что уже реально работает в Taris**: та же модель эмбеддингов, тот
   же принцип чанкинга и поиска. Цель — не изобретать заново, а **показать и доказать, что у
   Taris такая технология уже есть и работает** (это зафиксировано в архитектуре бота — файл
   `doc/architecture/knowledge-base.md` в проекте `sintaris-pl`), и дать вам работающий,
   независимый от Colab пример этого же механизма, который можно потрогать локально.

## Почему это не «с нуля», а именно Taris

В боте Taris уже год как реализован ровно такой же по сути пайплайн — «поиск базы знаний по
смыслу вопроса»:

| Шаг задания | Что в Taris | Файл |
|---|---|---|
| Модель эмбеддингов для русского языка (бесплатная) | `paraphrase-multilingual-MiniLM-L12-v2` — открытая многоязычная модель, понимает русский, работает локально без интернета и без оплаты | `core/bot_embeddings.py` (`EmbeddingService`), настройка `EMBED_MODEL` в `core/bot_config.py` |
| Загрузка «базы» (резюме → у нас документы базы знаний) | Загрузка PDF/DOCX/TXT, извлечение текста | `features/bot_documents.py` |
| Разбить текст на блоки (чанки) | Чанкинг по ~512 символам с учётом границ предложений | `features/bot_documents.py` (`_chunk_text`), константа `RAG_CHUNK_SIZE` |
| Построить векторную БД | Таблица эмбеддингов: `sqlite-vec` (Raspberry Pi) или `pgvector` (сервер) | `core/store_sqlite.py` / `core/store_postgres.py` |
| Поиск + структурированный вывод | Поиск по смыслу + текстовый поиск вместе, топ-K результатов со ссылкой на источник | `core/bot_rag.py` (`retrieve_context`), footer «Sources: …» |

То есть у Taris это уже готовая, проверенная в бою функция. Ваш реальный пример из документации
Taris — вопрос **«у меня болят суставы, что делать?»**, на который бот ищет подходящий
товар/протокол в базе знаний — это практически то же самое задание, что и «резюме под
вакансию», только предметная область — здоровье, а не подбор персонала.

## Что будет сделано (2 части)

### Часть 1 — таблица соответствия (документ)

Файл `02-сопоставление-с-taris.md`: построчно проходим оригинальное задание (`00-задание7.4.md`)
и для каждого пункта пишем — как именно этот пункт уже реализован в Taris, со ссылкой на
конкретный файл/функцию. Это и есть прямое доказательство «у нас это уже есть».

### Часть 2 — работающий локальный пример (код)

Чтобы задание можно было не только прочитать, но и **запустить и увидеть своими глазами**, я
соберу небольшой самостоятельный Python-проект внутри `Perr7.4/`, который повторяет тот же
пайплайн, что и в Taris — **на той же модели эмбеддингов**, но без необходимости поднимать
весь бот целиком. Проект НЕ трогает боевой код `sintaris-pl` и НЕ требует доступа к вашему
серверу — это самостоятельная демонстрация той же технологии.

Пайплайн (все пункты оригинального задания сохранены, просто на новых данных):

1. **Подготовка среды** — `requirements.txt` (pandas, sentence-transformers, numpy) + скрипт,
   который печатает версии библиотек при старте (чтобы не ловить сюрпризы от обновлений).
2. **База знаний вместо базы резюме** — небольшой учебный набор (~25-30 карточек) на тему
   нутрициологии/здоровья: детокс-протокол, снятие стресса, что приготовить из типовых
   продуктов, сон, витамины, суставы и т.д. Я напишу его сам как общеобразовательный пример
   (никаких реальных клиентских данных или закрытых материалов LR — это учебная имитация той
   же по смыслу базы). Структура — таблица (категория, заголовок, текст), как и просили в
   задании: посмотреть первые строки, посмотреть уникальные категории, оставить нужные колонки,
   превратить строку таблицы в связный текст.
3. **Эмбеддинги** — та же модель, что в Taris: `paraphrase-multilingual-MiniLM-L12-v2` через
   `sentence-transformers` (бесплатно, локально, без API-ключей).
4. **Чанкинг** — режем длинные записи на смысловые блоки тем же принципом, что в Taris
   (по абзацам/предложениям, ограничение по длине).
5. **Векторная база** — простое SQLite-хранилище эмбеддингов (без сторонней C-библиотеки
   `sqlite-vec`/`faiss` — в пути проекта есть кириллица, а такие библиотеки на Windows иногда
   ломаются именно из-за этого, см. `LESSONS-LEARNED.md`; обычный `sqlite3` + подсчёт схожести
   через `numpy` работает без таких рисков и для учебного объёма данных полностью достаточно).
6. **Поиск** — пользователь вводит вопрос свободным текстом (аналог «описания вакансии»),
   скрипт находит наиболее похожие по смыслу карточки и выводит структурированный результат:
   место в рейтинге, оценка схожести, заголовок, категория, отрывок текста.
7. **Тестовый прогон** — прогоняем несколько реалистичных вопросов (по образцу реальных
   вопросов из документации Taris: про суставы, про детокс, про меню из того, что есть в
   холодильнике) и сохраняем результат в файл — это и есть проверка, что поиск находит то, что
   нужно.

## Что нужно от вас перед реализацией

Ничего платного и никаких токенов — модель эмбеддингов бесплатная и работает локально,
интернет нужен только один раз, чтобы её скачать (после первого запуска работает офлайн).

## План тестирования

- Прогнать 5-6 тестовых вопросов из области нутрициологии/здоровья и вручную проверить: похожи
  ли найденные карточки на вопрос по смыслу (не только по совпадающим словам).
- Проверить структуру вывода — результат должен быть читаемым: понятно, что нашли и почему.
- Убедиться, что скрипты работают «с нуля» одной командой (после `pip install -r
  requirements.txt`) — без Google Colab, без интернета (кроме разовой загрузки модели).

## План демонстрации

- `demo.md` — как поставить и запустить локальный пример по шагам, плюс сохранённый лог тестовых
  запросов (`результаты-поиска.md` или похожий файл) — на случай, если проверяющий не будет сам
  запускать код.
- Отдельным пунктом — необязательный «бонус для вас лично»: короткая инструкция, как задать
  похожий вопрос вашему реальному боту Taris (Telegram или Web UI) и увидеть тот же механизм в
  проде, плюс где посмотреть метрики поиска (Admin Panel → RAG Stats). Этот шаг делаете вы сами
  в браузере/Telegram — у меня в этой среде нет доступа к вашему серверу и боту.

## Credentials / доступы

Не требуются — всё работает локально на бесплатной модели, без API-ключей.
