# Демонстрация — Perr7.4

Это задание — документальная демонстрация, не отдельный запускаемый проект. Показывать
проверяющему нечего запускать локально: всё доказательство — в разборе реального кода и реальных
случаев из практики Taris.

## Как показать результат проверяющему

1. Дать проверяющему ссылку на файлы в этой папке (репозиторий или прямые файлы):
   - [`02-как-это-реализовано-в-Taris.md`](02-как-это-реализовано-в-Taris.md) — основной документ:
     пошаговое сопоставление задания с реальным кодом Taris + два реальных примера из практики.
   - [`результаты.md`](результаты.md) — сверка пункт за пунктом с исходным заданием.
2. В документе есть точные ссылки на файлы и функции реального проекта `sintaris-pl`
   (`core/bot_rag.py`, `core/bot_embeddings.py`, `features/bot_documents.py` и др.) — при желании
   проверяющий может открыть эти файлы в репозитории `sintaris-pl` и увидеть код своими глазами.

## Необязательный бонус: живая демонстрация на вашем боте

Этот шаг делаете вы сами — у меня в этой рабочей среде нет доступа к вашему серверу или боту
Telegram/Web UI Taris.

1. Откройте чат с ботом Taris (Telegram или Web UI на `agents.sintaris.net` / `localhost:8080`).
2. Задайте вопрос по теме здоровья/нутрициологии, на которую в базе знаний точно есть материал,
   например: «у меня болят суставы, что посоветуешь?» или «что делать при детоксе?».
3. Покажите проверяющему:
   - сам ответ бота;
   - подпись «Sources: …» под ответом — список разделов документов, откуда взята информация (это
     и есть «структурированный и понятный вывод» из задания);
   - Admin Panel → 🔍 RAG / Knowledge Base → 📊 RAG Stats — статистику по количеству найденных
     фрагментов и скорости поиска.

Это займёт пару минут и наглядно покажет тот же пайплайн (эмбеддинги → векторный поиск →
структурированный ответ) не в виде кода, а как готовую рабочую функцию продукта.
