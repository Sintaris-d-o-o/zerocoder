# Концепция и план: Perr7.1 — сценарий в n8n для анализа записей звонков

## 1. Что делаем и зачем

Нужен рабочий сценарий в n8n, который выполняет три вещи:
1. Получает записи звонков по e-mail.
2. Расшифровывает их в текст (транскрибация) — **локально, без платного API распознавания речи** (запрет по заданию на "Chat GPT API" для этого шага).
3. Анализирует текст и достаёт из него полезные для бизнеса выводы: на что жаловался/сомневался клиент, в каком тоне шёл разговор, и что можно улучшить. Делаем это **двумя способами параллельно** — через GPT и через локальную модель — чтобы можно было сравнить качество и выбрать, что оставить в постоянной работе.

Результат — таблица в Google Sheets, куда автоматически падает строка с итогами по каждому обработанному звонку. Это готовый мини-инструмент отдела контроля качества: не нужно вручную слушать каждый звонок, чтобы понять, что клиенты возражают чаще всего.

## 2. Что уже есть и что решили по итогам вопросов

- **Записи для теста** — берём готовые из `Perr7.1/data/` (6 файлов mp3, реальные звонки отдела продаж).
- **Образец сценария от преподавателя** — тоже лежит в `Perr7.1/data/n8n-template-okk-fink.json`. Это оказался сценарий не в n8n, а в другом похожем сервисе (Make.com), но логику берём за основу: транскрибация → GPT достаёт возражения клиента и рекомендации по продажам → строка в Google-таблицу. Разница: у преподавателя транскрибация идёт через платный API OpenAI Whisper — нам это делать нельзя, поэтому эту часть заменяем на локальную.
- **Почта для приёма записей** — используем вашу существующую почту (`GOOGLE_MAIL` / `GOOGLE_MAIL_PWD` в `.env`) через IMAP.
- **Локальная транскрибация — важная находка.** На вашем сервере (`SSH_HOST`, он же хостит и сам n8n — `automata.dev2null.de` технически тот же сервер) уже работает бот «Тарис»: в `/opt/taris-docker` у него настроен и **проверенно работает** локальный движок распознавания речи `faster-whisper` (модель `small`, русский язык уже поддержан, файлы модели уже скачаны на диск — повторно качать не нужно). Это отличная новость: не нужно ничего собирать/компилировать заново (как я планировала раньше с whisper.cpp) и не нужно гадать, заведётся ли распознавание речи на этом процессоре (ARM) — она уже полтора месяца работает у бота «Тарис» для голосовых сообщений.
  Продакшн-бота мы не трогаем и не встраиваемся в его код (у него свой сайт с логином, лишний риск что-то сломать в рабочем сервисе). Вместо этого рядом ставим **свой отдельный маленький сервис** на том же сервере: то же самое проверенное распознавание речи, но отдельным процессом, под отдельной учётной записью, слушает только "изнутри" сервера (не наружу, безопасно). Раз n8n физически на этом же сервере — сценарий n8n просто обращается к этому сервису напрямую по внутреннему адресу, без лишних манипуляций с файлами по SSH на каждый звонок.
- **Локальная модель для анализа текста — тоже уже есть на сервере.** Кроме распознавания речи, на сервере уже крутится Ollama с моделью Qwen2.5-3B (используется ботом «Тарис» как запасной вариант вместо GPT). Её тоже переиспользуем — как второй, полностью локальный вариант анализа текста, по вашей просьбе сделать оба варианта (GPT и локальный).
- **Google Таблица** — вы дали `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (это ключи OAuth-доступа к Google). Разница с service account: с OAuth нужно один раз в браузере подтвердить доступ ("да, разрешаю читать/писать в эту таблицу") — это стандартный шаг, я подготовлю точную ссылку, останется один раз кликнуть "Разрешить". Дальше всё работает уже без участия человека.

## 3. Как это будет работать (пошагово)

```
Письмо с аудио-записью звонка
        │  (IMAP: n8n проверяет почтовый ящик)
        ▼
n8n забирает вложение (mp3/wav)
        │
        ▼
n8n отправляет аудио на локальный сервис распознавания речи
(он на том же сервере, что и n8n — тот же faster-whisper,
что уже работает у бота «Тарис», без обращения к OpenAI)
        │
        ▼
Сервис возвращает готовый текст звонка
        │
        ▼
Текст уходит на анализ ДВУМЯ способами параллельно:
        │
        ├──▶ Вариант A: модель GPT (OpenAI, по API)
        │
        └──▶ Вариант B: локальная модель Qwen2.5-3B
                (тоже уже работает на этом сервере через Ollama,
                без обращения к OpenAI)
        │
        ▼
Оба набора выводов (GPT и локальная модель) построчно
добавляются в Google-таблицу — рядом, для сравнения
```

**Почему транскрибация "локальная", а для анализа текста — два варианта?**
Запрет в задании на "Chat GPT API" привязан именно к распознаванию речи ("для транскрибации... без использования Chat GPT API") — сам голос никуда не отправляется на сторону, модель распознавания речи работает у вас на сервере. Анализ уже готового текста задание не запрещает делать через GPT — так и было у преподавателя в примере. По вашей просьбе делаем оба варианта: GPT (обычно точнее находит нюансы) и полностью локальную модель Qwen2.5-3B (без сторонних API вообще — тоже уже работает на этом сервере, используется ботом «Тарис») — можно будет сравнить качество и выбрать, что оставить в проде.

**Честная оговорка про "тон голоса".** Модель распознавания речи отдаёт только текст, без интонации, громкости, пауз. Поэтому "тон голоса" в таблице — это оценка GPT по тому, *как написана* реплика (вежливо/раздражённо/сухо и т.п.), а не по реальному звучанию голоса. Это стандартное ограничение при работе с текстовой расшифровкой — просто хочу, чтобы это было понятно, а не выглядело как недоделка.

## 4. Что попадёт в Google-таблицу

По одной строке на звонок, с результатами обеих моделей рядом — для сравнения:

| Дата | Файл | Отправитель | Транскрипт | GPT: возражения | GPT: тон голоса | GPT: другие выводы | Локальная модель: возражения | Локальная модель: тон голоса | Локальная модель: другие выводы |
|---|---|---|---|---|---|---|---|---|---|

"Другие выводы" — краткое резюме звонка и на что стоит обратить внимание (по аналогии с "3 улучшения для компании" у преподавателя).

## 5. План реализации

1. На сервере (`SSH_HOST`), в отдельной от продакшн-бота папке и учётной записи: поставить лёгкий сервис на основе уже проверенного `faster-whisper` (та же модель, что уже скачана и работает у бота «Тарис» — переиспользуем файлы модели, повторно не скачиваем). Сервис слушает только изнутри сервера (не наружу) и отдаёт готовый текст по запросу — «прими аудио, верни текст».
2. В n8n создать доступы (credentials): IMAP-почта, OpenAI (уже есть ключ в `.env`), Google Sheets (одноразовое подтверждение доступа в браузере через ваш `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`).
3. Собрать сам сценарий в n8n (через API n8n, чтобы весь сценарий сохранился как файл в репозитории — можно будет посмотреть код сценария, а не только картинку):
   - Триггер: новое письмо с вложением (IMAP)
   - Отправка вложения в сервис распознавания речи, получение текста
   - Параллельно: запрос к GPT (возражения / тон / выводы) и запрос к локальной модели Qwen2.5-3B через Ollama (тот же самый анализ)
   - Запись одной строки в Google-таблицу с результатами обеих моделей
4. Тестово отправить 6 записей из `data/` на выбранную почту и прогнать сценарий.

## 6. Что нужно в `.env`

Уже добавлено вами: `GOOGLE_MAIL`/`GOOGLE_MAIL_PWD` (почта для приёма записей, IMAP у Gmail стандартный — `imap.gmail.com:993`, отдельно указывать не нужно), `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` (доступ к Google Таблицам), `TARIS_DOCKER_PATH` (для справки, где на сервере лежит существующий STT).

Ещё понадобится: `GOOGLE_SHEET_ID` — ID таблицы, куда писать результаты. Создайте пустую Google-таблицу в своём Google Drive (например, «Perr7.1 — анализ звонков») и пришлите её ссылку/ID — остальное сделаю я.

Уже есть и переиспользуем: `SSH_HOST/SSH_PORT/SSH_USER/SSH_KEY_PATH` (разово — только для установки сервиса), `OPENAI_API_KEY`, `N8N_HOST/N8N_API_KEY`.

## 7. План тестирования

- Проверить, что локальная модель распознавания на сервере действительно понимает русскую речь — прогнать один файл из `data/` вручную по SSH до сборки всего сценария.
- Отправить все 6 записей из `data/` на почту и убедиться, что все 6 строк появились в таблице, без пропусков.
- Открыть транскрипт хотя бы одного звонка и сверить его с содержанием на слух — что распознавание не превратилось в бессвязный текст.
- Проверить строку в таблице на здравый смысл: возражения и выводы должны быть по делу, а не общими фразами не по теме звонка.
- Сравнить колонки GPT и локальной модели между собой на нескольких звонках — насколько локальная модель (намного меньше по размеру) справляется хуже/сопоставимо с GPT.

## 9. Риски / что стоит иметь в виду

- Сервер общий: на нём же крутится сайт на WordPress, сам n8n и бот «Тарис». Наш сервис распознавания речи делаем сознательно лёгким и отдельным от бота «Тарис» (не трогаем его код и его страницу входа), чтобы ничего в рабочих сервисах не сломать. Модель распознавания будет запускаться только когда приходит новый звонок — нагрузка разовая и небольшая.
- SSH-ключ (`SSH_KEY_PATH`) используется только один раз — чтобы установить наш сервис на сервер. В повседневной работе сценарий обращается к сервису по обычному сетевому запросу, SSH-ключ n8n не нужен и в credentials n8n не сохраняется.
- Ваша почта (`GOOGLE_MAIL`) — обычный пароль в `.env`, а не отдельный пароль приложения. Если Google заблокирует вход по паролю (частая история для Gmail без официального "пароля приложения"), на месте попробуем это решить — либо включить пароль приложения в настройках аккаунта, либо взять другую почту.
