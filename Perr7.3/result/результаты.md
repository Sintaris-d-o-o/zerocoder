# Результаты: Perr7.3 — SMM-ассистент (подтверждение реализации в Taris)

Документ отвечает на один вопрос: **что из задания Perr7.3 уже работает в Taris и где
именно это лежит в коде.** Новой разработки не велось. Всё перечисленное развёрнуто на
боевом сервере TariStation1 (версия 2026.8.83) и открывается по обычному адресу
веб-приложения.

Пути к файлам даны от корня проекта Taris (`src/`).

---

## 1. Аутентификация и авторизация

### 1.1 Регистрация новых пользователей

| Что | Где |
|---|---|
| Страница | `GET /register` → шаблон `web/templates/register.html` |
| Обработка формы | `POST /register` (`bot_web.py: register_submit`) |
| Создание учётной записи | `security/bot_auth.py: create_account()` |
| Хеш пароля | `bcrypt.hashpw(..., bcrypt.gensalt(rounds=12))` |

Проверки при регистрации (все серверные, до записи в базу):

* почта — по регулярному выражению `^[^@\s]+@[^@\s]+\.[^@\s]+$`;
* имя пользователя — не короче 3 символов, пароль — не короче 4;
* занятость имени — `find_account_by_username()`;
* необязательный код привязки к Telegram — `validate_web_link_code()`, 15 минут жизни.

Дополнительно к заданию: **первый** зарегистрировавшийся получает активный статус, все
последующие — `pending`, то есть войти не могут, пока администратор не одобрит заявку
(`POST /admin/user/{user_id}/approve`). Самостоятельная регистрация даёт роль `guest`, а
не полноправного пользователя: решение администратора «это живой человек» и решение «дать
ему все функции» — разные решения. Скриншот `02-регистрация.png`.

### 1.2 Вход в систему

`POST /login` (`bot_web.py: login_submit`):

1. `find_account_by_username()` — поиск учётной записи;
2. `verify_password()` — сверка с bcrypt-хешем;
3. проверка статуса: `pending` и `blocked` получают понятную ошибку, а не «неверный пароль»;
4. `create_token()` — подписанный JWT (HS256, срок 30 дней);
5. cookie `taris_token`: `httponly=True`, `samesite="lax"`, `max_age=30 дней`.

Ошибки не выдают лишнего: несуществующее имя и неверный пароль дают один и тот же текст.
Скриншот `01-вход.png`.

### 1.3 Защита маршрутов

В Taris нет «страниц по умолчанию открытых»: **каждый** маршрут начинается с

```python
user = _get_current_user(request)
if not user:
    return _redir("/login", 302)
```

`_get_current_user()` (`bot_web.py`) читает cookie, проверяет подпись и срок JWT и —
важная деталь — **перечитывает роль и статус из базы**. Поэтому понижение роли или
блокировка действуют немедленно, а не после того, как пользователь выйдет и войдёт.

Поверх этого — ролевые ограничения. Для агентов (в том числе контент-стратега):

```python
def _agents_role_guard(user: dict) -> None:
    if not user or user.get("role") not in ("admin", "developer", "advanced"):
        raise HTTPException(status_code=403, ...)
```

Роли: `guest` → `user` → `advanced` → `admin` → `developer` (см.
`doc/users/roles-overview.md`). Скриншот `03-защита-маршрута.png` — попытка открыть
страницу статистики без входа заканчивается формой входа.

### 1.4 Выход

`GET /logout` — `resp.delete_cookie(COOKIE_NAME)` и перенаправление на `/login`.

### 1.5 Сверх задания

* **Восстановление пароля:** `/forgot-password` → одноразовый токен (60 минут, таблица
  `web_reset_tokens`) → письмо через SMTP → `/reset-password/{token}`.
* **Смена имени пользователя и пароля** в профиле, смена пароля администратором.
* **Привязка Telegram ↔ веб:** один человек — одна учётная запись в обоих каналах.

## 2. Генерация контента

### 2.1 Текст поста по заданным параметрам

Параметры собираются формой на `/agents/content`: тема / аудитория / цель, площадка,
использовать ли документы пользователя как контекст (скриншот `06-форма-генерации.png`).

| Что | Где |
|---|---|
| Контент-план из 7 постов | `POST /agents/content/plan` |
| Развернуть пост №N | `POST /agents/content/post` |
| Правка своими словами | тот же маршрут с полем `correction` |
| Сама генерация | `bot_web.py: _generate_content()` — сначала сценарий N8N, если он настроен, иначе языковая модель |
| Генерация в Telegram | `features/bot_content.py: _generate_content_with_llm()` |

Провайдер модели переключается настройкой `LLM_PROVIDER` (`openai`, `ollama`, и другие) —
задание требует OpenAI API, этот путь рабочий; на боевом сервере по умолчанию стоит
локальная модель, чтобы не платить за каждый черновик.

### 2.2 Генерация изображений

| Что | Где |
|---|---|
| Кнопка на готовом посте | `POST /agents/content/image` |
| Описание сцены (ИИ) | `core/bot_images.py: describe_image_for_post()` |
| Сама картинка | `core/bot_images.py: generate_image()` — OpenAI Images, `gpt-image-1` или `dall-e-3` |
| Хранение | файл `CONTENT_MEDIA_DIR/<пользователь>/<id>.png`, отдаётся маршрутом `/agents/content/media/...` с проверкой владельца |

Две ступени (сначала описание сцены, потом рисование) — как в примере преподавателя; если
отдать модели изображений сам пост, получится картинка, набитая нечитаемыми буквами.
Ссылка провайдера не сохраняется принципиально: она перестаёт открываться примерно через
час, и сохранённый пост показывал бы пустую рамку.

### 2.3 История сгенерированного контента

Две независимые сущности, обе на пользователя:

| Что хранится | Где |
|---|---|
| Пост как объект: тема, площадка, текст, картинка, статус, канал, ссылка | таблица `content_posts` (`core/store_content.py`) |
| Наблюдения показателей: лайки, просмотры, репосты, комментарии, подписчики, источник, дата | таблица `content_metrics` |
| Черновики и контент-планы как текст | заметки пользователя (`cp_…`, `post_…`) |

Просмотр — `/agents/content/stats` (скриншот `07-история-публикаций.png`): карточки итогов,
диаграмма по месяцам, популярные темы и таблица со строкой на каждый пост.

## 3. Интеграция с ВКонтакте

`features/bot_content_vk.py` — полный аналог связки `vk_publisher.py` + `vk_stats.py` из
примера преподавателя:

| Функция | Метод VK API | Назначение |
|---|---|---|
| `upload_photo()` | `photos.getWallUploadServer` → загрузка → `photos.saveWallPhoto` | картинка как вложение |
| `publish()` | `wall.post` (`from_group=1`, `owner_id=-<group>`) | публикация поста |
| `fetch_post_stats()` | `wall.getById` | лайки, просмотры, комментарии, репосты |
| `fetch_followers()` | `groups.getById` (`fields=members_count`) | число подписчиков |
| `sync_metrics()` | оба | обновить показатели всех опубликованных постов за один заход |

Публикация из веба: `POST /agents/content/publish` с `target=vk`. Из Telegram — кнопка
«🅥 ВКонтакте» на готовом посте.

**Статус публикации сохраняется** (`core/store_content.py: mark_published()`):
`status='published'`, `published_at`, `channel='vk'`, `external_id` (номер записи) и
`external_url` (`https://vk.com/wall-<group>_<post_id>`). Сразу после публикации
открывается ряд наблюдений (`record_metrics(..., source='vk')`), чтобы опубликованный пост
не был невидим в статистике.

Три отличия от примера преподавателя, сделанные намеренно:

1. **Токен и ID сообщества хранятся отдельно для каждого пользователя** (`user_prefs`:
   `content_pub_vk_token`, `content_pub_vk_group`), а не в `config.py`. Одно сообщество
   принадлежит одному человеку; общий токен в конфигурации позволил бы любому
   пользователю сервера писать в чужой паблик.
2. **Сбой загрузки картинки не отменяет публикацию текста** — текст написал человек,
   терять его из-за сбоя фотоэндпоинта хуже.
3. **Число подписчиков запрашивается один раз на заход**, а не по разу на пост: сорок
   одинаковых запросов — верный способ получить ограничение по частоте.

## 4. Интерфейс

| Требование | Страница | Скриншот |
|---|---|---|
| Страница логина | `/login` | `01-вход.png` |
| Страница регистрации | `/register` | `02-регистрация.png` |
| Дашборд | `/` — приветствие, ближайшие события, заметки, быстрые действия | `04-дашборд.png` |
| Форма генерации постов | `/agents/content` (плитка «Контент-стратег» на `/agents`) | `05-агенты.png`, `06-форма-генерации.png` |
| История публикаций | `/agents/content/stats` | `07-история-публикаций.png` |
| Настройки | `/profile` — имя, пароль, язык, тема, часовой пояс, привязка Telegram, голос, память | `08-профиль-и-настройки.png` |

Интерфейс на четырёх языках (ru / en / de / sl), язык переключается на самой странице
входа и запоминается в учётной записи.

**Управление настройками ВК — единственный пункт, закрытый частично.** Токен и ID
сообщества задаются в Telegram-канале интерфейса: ✍️ Контент-стратег → ⚙️ Настройки
публикации (`features/bot_content.py: show_pub_config()`, `on_pub_config_input()`).
Веб-интерфейс эти настройки **читает** (и предлагает ВКонтакте как цель публикации, когда
они заданы), но формы для их ввода в вебе нет — вместо неё выводится подсказка, где их
задать. Причина простая и честная: секрет, введённый в Telegram, не проходит через журнал
веб-сервера и историю браузера. Добавить форму в веб — работа примерно на час, но это уже
была бы новая разработка, а не подтверждение.

## 5. Технологии: чем и почему отличается стек

| Задание | В Taris | Почему |
|---|---|---|
| Flask | **FastAPI + Jinja2** | Тот же шаблон приложения (маршруты + шаблоны + сессии), но с типизированными параметрами форм, асинхронными обработчиками и встроенной валидацией. Taris — не учебный проект: у него уже был веб-интерфейс на FastAPI, голосовой канал и REST API, переписывать всё на Flask ради совпадения по названию бессмысленно |
| SQLite | **SQLite и PostgreSQL — один и тот же код** | Адаптер выбирается настройкой `STORE_BACKEND`: SQLite на слабых устройствах и в тестах, PostgreSQL на боевом сервере. Схема описывается один раз, типы для SQLite получаются заменой (`core/store_content.py`) |
| VK API SDK | **прямые вызовы HTTP** (`requests`) | Ровно как в примере преподавателя: нужны четыре метода, отдельная зависимость ради них не нужна |
| Werkzeug для хеширования | **bcrypt, work factor 12** | Отдельная, специализированная библиотека; `bcrypt.checkpw` сравнивает за постоянное время |
| Flask-WTF / WTForms | **Form-параметры FastAPI + проверки в маршруте** | Валидация серверная и обязательная; типы полей объявлены в сигнатуре обработчика |
| Flask session | **подписанный JWT в httpOnly-cookie** | Не требует серверного хранилища сессий, переживает перезапуск, роль и статус перечитываются из базы на каждом запросе |

**Что стоит знать честно про CSRF.** В примере преподавателя защита от CSRF приходит
вместе с Flask-WTF. В Taris её нет в виде токена: cookie помечена `SameSite=Lax`, что
запрещает браузеру отправлять её при межсайтовом POST, — это работает, но это более слабая
гарантия, чем токен в форме. Пункт задания «валидация форм» это не нарушает, но в
production-приложении токен стоит добавить.

## 6. Чем реализация Taris выходит за рамки задания

Не для оценки, а чтобы не выглядело, будто «просто совпало»:

* **два интерфейса вместо одного** — веб и Telegram-бот, обе стороны полнофункциональны и
  работают с одними и теми же данными;
* **роли и одобрение регистраций**, а не просто «вошёл — значит всё можно»;
* **четыре языка интерфейса** и восстановление пароля по почте;
* **показатели как история наблюдений**, а не одна строка на пост — иначе диаграмма по
  месяцам невозможна;
* **вовлечённость вычисляется**, а не хранится, поэтому не может разойтись с лайками и
  просмотрами рядом;
* **57 автоматических тестов** только по контент-части: офлайн-проверки, модульные тесты и
  браузерные тесты против боевого сервера (см. `проверка.md`).
