# Архитектура Taris в объёме задания Perr7.3

Общий обзор — без деталей, которые к заданию не относятся. Задача документа: показать, из
каких частей собрано то, что задание требует построить на Flask, и как эти части связаны.

---

## 1. Слои

```
        Telegram-бот                        Веб-приложение (браузер)
   telegram_menu_bot.py                          bot_web.py
   (кнопки, callback-и)                    (FastAPI-маршруты + Jinja2)
            │                                        │
            └──────────────┬─────────────────────────┘
                           ▼
                 features/  — сценарии работы
    bot_content.py · bot_content_vk.py · bot_notify.py · bot_campaign.py · …
                           │
                           ▼
                  core/  — общие библиотеки
    bot_llm.py (текст)   bot_images.py (картинки)   bot_db.py (соединение)
    store_content.py (посты и показатели)   store_sqlite.py / store_postgres.py
                           │
                           ▼
              security/bot_auth.py  — учётные записи, пароли, токены
                           │
                           ▼
                    SQLite  или  PostgreSQL
```

Правило, которое здесь важнее прочих: **логика живёт в `features/` и `core/`, а не в
интерфейсе**. Поэтому Telegram и веб делают одно и то же и не могут разойтись в поведении:
и кнопка в боте, и форма в браузере вызывают одну и ту же функцию.

Сопоставление с примером преподавателя на Flask:

| Пример (Flask) | Taris | Комментарий |
|---|---|---|
| `app/__init__.py` (`create_app`) | `bot_web.py` (объект `app`, middleware, шаблоны) | точка сборки приложения |
| `app/auth.py` (blueprint) | маршруты `/login`, `/register`, `/logout` + `security/bot_auth.py` | логика вынесена из маршрутов в модуль |
| `app/smm.py` (blueprint) | маршруты `/agents/content*` + `features/bot_content.py` | то же разделение |
| `app/models.py` (SQLAlchemy) | `core/store_*.py` (адаптеры хранилища) | вместо ORM — явные запросы и один адаптер на СУБД |
| `generators/text_gen.py` | `core/bot_llm.py` + `_generate_content()` | выбор провайдера внутри |
| `generators/image_gen.py` | `core/bot_images.py` | плюс хранение файла и защита пути |
| `social_publishers/vk_publisher.py` | `features/bot_content_vk.py` | публикация |
| `social_stats/vk_stats.py` | он же | статистика — тот же API, тот же модуль |
| `config.py` с ключами | переменные окружения + `user_prefs` для персональных токенов | секретов в коде нет |

## 2. Модель данных

Только таблицы, относящиеся к заданию.

```
web_accounts                         users (Telegram)
├─ user_id (PK)                      ├─ chat_id (PK)
├─ username (unique)   ◄──связка──►  ├─ username
├─ pw_hash  (bcrypt)                 ├─ role
├─ role, status                      └─ language
├─ telegram_chat_id ─────────────────┘
├─ email, language, timezone
└─ is_expert, is_academy_admin

content_posts                        content_metrics
├─ id (PK)                           ├─ id (PK)
├─ chat_id  (владелец)               ├─ post_id ──► content_posts.id
├─ topic, platform, title, body      ├─ chat_id
├─ image_path, image_prompt          ├─ collected_at, source (manual|telegram|vk)
├─ plan_slug, post_index, lang       ├─ likes, views, shares, comments
├─ status (draft|published)          └─ followers
├─ published_at, channel
└─ external_id, external_url

web_reset_tokens — одноразовые токены восстановления пароля (60 мин)
```

Три решения, которые стоит назвать:

1. **Показатели — временной ряд, а не колонки поста.** Каждое обновление добавляет строку
   с датой. Затирание уничтожило бы историю, из которой строится диаграмма по месяцам.
2. **Вовлечённость не хранится.** Она вычисляется при чтении:
   `(лайки + репосты + комментарии) ÷ просмотры`. Хранимое значение рано или поздно
   разойдётся со слагаемыми, которые печатаются рядом.
3. **Подписчики агрегируются как максимум, а не сумма.** Одна аудитория, замеренная на
   сорока постах, — это не сорок аудиторий.

Схема описывается один раз (для PostgreSQL), вариант для SQLite получается заменой типов —
так две базы не могут разойтись:

```python
_SCHEMA_SQLITE = [s.replace("TIMESTAMPTZ DEFAULT NOW()", "TEXT")
                   .replace("TIMESTAMPTZ", "TEXT")
                   .replace("BIGINT", "INTEGER") for s in _SCHEMA_PG]
```

## 3. Процесс: вход и защита маршрутов

```
браузер                    bot_web.py                    security/bot_auth.py
   │  POST /login  ────────────►                                  │
   │                    find_account_by_username() ──────────────► │ SELECT
   │                    verify_password() ─────────────────────►   │ bcrypt.checkpw
   │                    проверка status (pending / blocked)        │
   │                    create_token() ────────────────────────►   │ JWT HS256, 30 дней
   │  ◄──── Set-Cookie: taris_token (httpOnly, SameSite=Lax)       │
   │                                                               │
   │  GET /agents/content ─────►                                   │
   │                    _get_current_user()                        │
   │                      ├─ verify_token()  (подпись + срок)      │
   │                      └─ роль и статус ПЕРЕЧИТЫВАЮТСЯ из БД    │
   │                    _agents_role_guard(user)  → 403, если роль ниже advanced
   │  ◄──── страница или редирект на /login                        │
```

Почему роль перечитывается: если она берётся только из токена, понижение прав или
блокировка вступают в силу лишь после того, как пользователь сам выйдет и войдёт, — то
есть ровно тогда, когда этого никто не контролирует.

## 4. Процесс: генерация поста и картинки

```
форма (тема / аудитория / цель, площадка, использовать ли документы)
        │
        ▼
POST /agents/content/plan ──► _generate_content()
        │                        ├─ сценарий N8N, если настроен
        │                        └─ иначе языковая модель (LLM_PROVIDER)
        ▼
контент-план из 7 постов  ──► выбор поста №N ──► POST /agents/content/post
        │
        ▼
готовый текст поста
        │
        ├─ POST /agents/content/image
        │        ├─ describe_image_for_post()  — ИИ описывает СЦЕНУ поста
        │        │      (+ тема дописывается программно: слабая модель уходит от темы)
        │        └─ generate_image()           — OpenAI Images → файл на диске
        │
        ├─ POST /agents/content/post/save  ──► content_posts (черновик)
        └─ POST /agents/content/post/download ──► файл .md
```

Ключ API берётся из общего хранилища ключей (то же значение, что и для текста), а не из
отдельной переменной: иначе при смене ключа где-то остаётся старая копия.

## 5. Процесс: публикация и статус

```
POST /agents/content/publish   (target = telegram | vk)
        │
        ├─ telegram ──► sendPhoto (картинка + подпись) или sendMessage
        │                   длиннее 1024 символов → фото и текст двумя сообщениями
        │
        └─ vk ───────► photos.getWallUploadServer → загрузка → photos.saveWallPhoto
                       wall.post(from_group=1, owner_id=-<group>, attachments=photo…)
        │
        ▼
mark_published(post_id, channel, external_id, external_url)
        │           content_posts: status='published', published_at, ссылка на запись
        ▼
record_metrics(..., source='telegram' | 'vk')      ← открывается ряд наблюдений
        │
        ▼
/agents/content/stats — карточки, диаграмма по месяцам, темы, таблица показателей
        ▲
        └── обновление чисел: вручную (форма или строка «245 3200 18000» в боте)
            или автоматически — «🔄 Обновить из ВКонтакте» (wall.getById, groups.getById)
```

Почему обновление вручную вообще существует: **Telegram Bot API не сообщает боту ничего о
записи в канале** — ни просмотров, ни реакций, ни числа подписчиков. Для Telegram числа
вводит человек; для сообщества ВКонтакте они читаются из API. Эта граница названа прямо в
интерфейсе, под таблицей показателей.

Куда публиковать вообще можно: только Telegram-канал и сообщество ВКонтакте
(`PUBLISHABLE_PLATFORMS`). Для поста, написанного под Instagram, LinkedIn, YouTube,
рассылку или сайт, страница прямо говорит, что бот туда публиковать не может, и предлагает
скачать текст и картинку.

## 6. Конфигурация и секреты

| Что | Где хранится |
|---|---|
| Ключ OpenAI, DSN базы, токен Telegram-бота | переменные окружения (`~/.taris/bot.env`), в репозиторий не попадают |
| Секрет подписи JWT | файл `~/.taris/web_secret.key`, создаётся сам, права `0600` |
| Токен и ID сообщества ВКонтакте | `user_prefs` — **отдельно для каждого пользователя** |
| Токен бота и канал для публикации | там же, отдельно для каждого пользователя |
| Сгенерированные картинки | `CONTENT_MEDIA_DIR` (каталог данных, не внутри исходников) |

В `.env.example` перечислены только **имена** переменных с заглушками — это часть правил
проекта, а не оформление: документ, попавший в репозиторий с настоящим значением,
становится утечкой в момент публикации.

## 7. Развёртывание

| Компонент | На боевом сервере |
|---|---|
| Веб-приложение | `taris-web.service` (systemd, пользовательский юнит), uvicorn на 8080 |
| Telegram-бот | `taris-telegram.service` |
| База | PostgreSQL 14 |
| Публикация наружу | Nginx → обратный SSH-туннель → сервер |
| Развёртывание | `src/setup/taris_deploy.sh` — сначала `--action analyze` (только чтение), затем `deploy`: копирование, миграция схемы, перезапуск, проверка журнала и smoke-тесты |

Схема таблиц контента создаётся идемпотентно при первом обращении
(`core/store_content.py: init_schema()`), отдельного скрипта миграции не требуется.
