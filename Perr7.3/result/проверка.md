# Как проверить самому: Perr7.3 в работающем Taris

Документ для проверяющего. Ничего разворачивать не нужно — всё работает на боевом сервере
(TariStation1, версия 2026.8.83). Адрес и учётные данные тестовой записи — в `.env`
проекта Taris (`TS1_WEB_URL`, учётная запись `pw_testuser_3804`).

---

## 1. Аутентификация — 4 проверки по минуте каждая

| Проверка | Что сделать | Что должно произойти |
|---|---|---|
| Защита маршрутов | Открыть `/agents/content/stats` в окне без входа | Форма входа вместо страницы (скриншот `03-защита-маршрута.png`) |
| Вход | Ввести логин и пароль | Дашборд; в браузере появляется cookie `taris_token` с флагом HttpOnly |
| Неверный пароль | Ввести любой неправильный пароль | Та же страница с ошибкой; текст одинаков для «нет такого пользователя» и «пароль не тот» |
| Выход | Нажать «Выход» | Возврат к форме входа, cookie удалена; открыть внутреннюю страницу снова нельзя |

Регистрацию можно посмотреть на `/register` (скриншот `02-регистрация.png`). Создавать
учётную запись не обязательно: вторая и последующие самостоятельные регистрации попадают в
статус «ожидает решения», и вход для них закрыт до одобрения администратором — это
поведение по замыслу, а не ошибка.

Проверить хеширование можно по коду: `src/security/bot_auth.py`, строки с
`bcrypt.hashpw(..., bcrypt.gensalt(rounds=12))` и `bcrypt.checkpw(...)`. Пароль в открытом
виде нигде не хранится и не логируется.

## 2. Генерация контента — один проход

1. **Агенты → ✍️ Контент-стратег** (скриншоты `05-агенты.png`, `06-форма-генерации.png`).
2. Ввести тему, например: «Путешествия и уютные маршруты по Европе. Аудитория —
   самостоятельные путешественники 30–45 лет. Цель — подписки».
3. **⚡ Генерировать** → через 20–60 секунд появится контент-план из 7 постов.
4. **📝 #1** → готовый текст поста.
5. **🖼 Сгенерировать картинку** → через 20–40 секунд появится иллюстрация.
6. **💾 Сохранить черновик** → пост попадает в историю; рядом «⬇️ Скачать» и
   «⬇️ Скачать картинку».

Результат этого прохода на живом сервере — в соседней папке задания Perr7.2:
`Perr7.2/result/screenshots/` и `пример-сгенерированной-картинки.png`.

## 3. История и статус публикаций

Ссылка **📊 Статистика публикаций** в правом верхнем углу страницы агента, либо адрес
`/agents/content/stats` (скриншот `07-история-публикаций.png`):

* карточки: постов, опубликовано, лайки, просмотры, подписчики, вовлечённость, с картинкой;
* столбчатая диаграмма «Публикации по месяцам»;
* популярные темы;
* таблица: строка на пост, статус («черновик» / «опубликован»), ссылка на запись во
  ВКонтакте, редактируемые поля лайков/просмотров/подписчиков.

Изменить числа и нажать «Сохранить» — карточки пересчитаются. Это и есть «сохранение
статуса публикации» и «просмотр истории» из задания в рабочем виде.

## 4. ВКонтакте

Публикация требует токена сообщества, поэтому проверяется на своём паблике:

1. В Telegram-боте: **🤖 Агенты → ✍️ Контент-стратег → ⚙️ Настройки публикации** — ввести
   токен сообщества (права `wall`, `photos`) и числовой ID сообщества.
2. После этого в вебе на готовом посте появится выбор цели «Сообщество ВКонтакте», а в
   Telegram — кнопка «🅥 ВКонтакте».
3. После публикации в таблице истории у поста появится статус «опубликован» и ссылка вида
   `https://vk.com/wall-<группа>_<запись>`.
4. Кнопка **🔄 Обновить из ВКонтакте** подтянет лайки, просмотры, комментарии, репосты и
   число подписчиков прямо из VK API.

Код без запуска: `src/features/bot_content_vk.py` — `publish()`, `fetch_post_stats()`,
`fetch_followers()`, `sync_metrics()`.

## 5. Автоматические тесты

Тесты по контент-части (57 штук) — то же подтверждение, только машинное:

```bash
# 35 модульных тестов агента (офлайн)
PYTHONPATH=src python -m pytest src/tests/test_content_strategy.py -q

# 12 офлайн-проверок расширения: схема в обеих БД, арифметика статистики,
# защита пути к картинке, устойчивость генерации, соответствие площадки форме публикации
python src/tests/test_voice_regression.py --test t_content_agent

# 10 браузерных тестов против работающего сервера
PICO_BASE_URL=<адрес> PICO_ADMIN_USER=<логин> PICO_ADMIN_PASS=<пароль> \
  python -m pytest src/tests/ui/test_ui.py::TestContentStatisticsWebUI -q
```

Аутентификация покрыта отдельно: класс `TestAuth` в `src/tests/ui/test_ui.py` — форма
входа отдаётся, неверный пароль отклоняется, защищённая страница без сессии ведёт на вход.

```bash
PICO_BASE_URL=<адрес> python -m pytest src/tests/ui/test_ui.py::TestAuth -q
```
