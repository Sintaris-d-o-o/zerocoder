# Perr1.6. Первый проект на сервере и его стабильная работа

Оригинал урока: `university.zerocoder.ru`, модуль 1. Текст задания вставлен пользователем.


Разверни свой первый проект на сервере и настрой его стабильную работу 🚀

Что нужно сделать:
1️⃣ Подготовить и запустить проект локально
Создать простой Python-проект (например, Flask-приложение или любой другой минимальный сервер)
Создать виртуальное окружение
Установить зависимости через requirements.txt
Запустить проект локально
Проверить, что он открывается в браузере
📌 Важно: проект должен корректно работать до деплоя

2️⃣ Перенести проект на сервер через FTP
Установить FTP-клиент (например, FileZilla)
Подключиться к серверу (IP, логин, пароль, порт)
Создать папку проекта на сервере
Перенести файлы проекта (без venv)
Проверить, что файлы успешно загружены
3️⃣ Запустить проект на сервере
Через терминал:

Подключиться к серверу
Перейти в папку проекта
Создать и активировать виртуальное окружение
Установить зависимости
Запустить проект
📌 Проверить:

Открывается ли проект по http://IP:порт
4️⃣ Настроить работу в фоне через screen
Запустить screen
Запустить проект внутри screen
«Свернуть» сессию (Ctrl + A → D)
Проверить, что проект продолжает работать после закрытия терминала
Посмотреть список сессий (screen -ls)
5️⃣ Запустить проект через Docker
Создать или использовать готовый Dockerfile
Собрать Docker-образ
Запустить контейнер с пробросом портов
Проверить работу проекта в браузере
📌 Дополнительно:

Запустить контейнер в фоне (d)
6️⃣ Обновить проект через GitHub
Залить проект в GitHub
Клонировать его на сервер
Внести изменения локально и сделать push
На сервере выполнить git pull
Пересобрать Docker-образ
Перезапустить контейнер
📌 Проверить: изменения применились

Формат сдачи
Необходимо предоставить:

1️⃣ Скриншоты:
работающего проекта локально
файлов на сервере (через FTP или ls)
запуска проекта на сервере
screen-сессии (screen -ls)
работы приложения в браузере по IP
Docker (сборка образа и запуск контейнера)
2️⃣ Краткое описание (5–10 предложений):
что такое деплой и зачем он нужен;
чем отличается запуск локально и на сервере;
в чем разница между FTP и GitHub;
зачем нужен Docker;
какой способ деплоя показался тебе самым удобным и почему;
с какими трудностями ты столкнулся и как их решил.
🔥 Это задание — твой первый шаг к реальному продакшн-развёртыванию. После него ты сможешь запускать свои проекты так, чтобы ими могли пользоваться другие люди.
