## 1. Taris на VPS dev2null.de в Docker

Файлы: `sintaris-pl/deploy/system-configs/vps/docker/`.

### Dockerfile (целиком, без изменений)

```dockerfile
# Taris OpenClaw — Docker image for VPS deployment (aarch64 / linux/arm64)
#
# Build context: /opt/taris-docker/
# Source code:   mounted from /opt/taris-docker/app/ at runtime
# Data:          /opt/taris-docker/data/ (whisper cache, piper models)
#
# Usage (in /opt/taris-docker/):
#   docker build -t taris-vps .
#   docker compose up -d

FROM python:3.12-slim

# System packages: ffmpeg for audio encoding/decoding, libopus for OGG
RUN apt-get update && apt-get install -y --no-install-recommends \
        ffmpeg \
        libopus0 \
        libsndfile1 \
        && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Install Python dependencies (separate layer for build cache)
COPY requirements.docker.txt /tmp/requirements.docker.txt
RUN pip install --no-cache-dir --upgrade pip && \
    pip install --no-cache-dir -r /tmp/requirements.docker.txt

ENV PYTHONPATH=/app
ENV PYTHONUNBUFFERED=1

# Source code is mounted at runtime via docker-compose volume
# Default CMD is overridden per-service in docker-compose.yml
CMD ["python3", "telegram_menu_bot.py"]
```

### docker-compose.yml (сайт; бот устроен так же)

```yaml
# Web UI port:  8090 (nginx proxies /supertaris-vps/ → 127.0.0.1:8090)
# Update flow:  rsync src/ → /opt/taris-docker/app/ && docker compose up -d
  taris-web:
    image: taris-vps:latest
    container_name: taris-vps-web
    network_mode: host            # listens on 0.0.0.0:8090 (set via --port in command)
    env_file: /opt/taris-docker/bot.env
    volumes:
      - /opt/taris-docker/app/src:/app:ro                          # source code
      - /opt/taris-docker/userdata/notes:/root/.taris/notes        # user notes (persisted)
      ...
    command: >
      python3 -m uvicorn bot_web:app
      --host 0.0.0.0
      --port 8090
      --root-path /supertaris-vps
    restart: unless-stopped
```

Что здесь видно по пунктам задания:
- `docker build -t taris-vps .` и `docker compose up -d` — сборка образа и запуск в фоне (`-d`);
- `--host 0.0.0.0 --port 8090` — сайт слушает все адреса сервера, а не только локальный;
- `restart: unless-stopped` — контейнер сам поднимается после сбоя и перезагрузки, поэтому
  `screen` не нужен;
- код подключается в контейнер папкой (`volumes`), поэтому при обновлении кода образ
  пересобирать не нужно, достаточно перезапустить контейнер. Пересборка нужна только при
  смене зависимостей (`requirements.docker.txt`).

### Перенос файлов на сервер (`deploy.sh`, `update.sh`)

```
Upload with: pscp -pw PASSWORD -r src/ stas@<сервер>:/opt/taris-docker/app
```

Файлы переносятся не по FTP, а по **SCP** (копирование через SSH, программа `pscp` из PuTTY).
Переносится только папка `src/`, без виртуального окружения: зависимости ставятся внутри
образа. Скрипт написан до 11.09.2026, когда на dev2null.de закрыли вход по паролю (см. Perr1.5); с тех пор
тот же `pscp`/`scp` работает по SSH-ключу.

`update.sh` после переноса перезапускает оба контейнера и показывает их состояние и последние
строки журнала:

```bash
sudo docker restart taris-vps-telegram taris-vps-web
sleep 3
sudo docker ps | grep taris-vps
sudo docker logs taris-vps-web 2>&1 | tail -8
```

Состояние на сервере по реестру `sintaris-srv` (`09-vps-software-deployment.md`):

| Контейнер | Образ | Папка | Порт | Статус |
|---|---|---|---|---|
| `taris-vps-web` | `taris-vps:latest` | `/opt/taris-docker/` | 8090 | работает |
| `taris-vps-telegram` | `taris-vps:latest` | `/opt/taris-docker/` | — | работает |

## 2. Свой образ из GitHub-репозитория на dev2null.de: n8n task runners

Репозиторий `Worksafety-superassistant` на GitHub клонирован на dev2null.de. Из него
собирается собственный Docker-образ с Python-библиотеками для узлов n8n.
Документация `sintaris-srv/vps-admin/docs/05-n8n-vps-setup.md`:

```bash
# Rebuild if Python packages change:
cd ~/Worksafety-superassistant/deployment/runners
sudo docker build -t worksafety-runners:latest -f Dockerfile.runners .
sudo docker compose -f /opt/n8n-docker/docker-compose.yml up -d n8n-runners
```

Скрипт `deployment/runners/deploy_runner.sh` делает то же по шагам: `docker build`, затем
останавливает и удаляет старый контейнер (`docker stop`, `docker rm`), запускает новый в фоне
(`docker run -d`) и проверяет, что внутри доступны нужные библиотеки (`docker exec … python3`).

перезапуск → проверка, что изменения применились.

## 4. Работа в фоне: сервис из задания 7.1 на dev2null.de

Запуск из [Perr7.1/02-развертывание.md](../../Perr7.1/02-развертывание.md):

```
PERR71_STT_TOKEN=... nohup ./venv/bin/python -m uvicorn stt_service:app --host 0.0.0.0 --port 8098 > service.log 2>&1 &
```

Журнал `sintaris-srv/vps-admin/docs/vps-activity-log.md`, запись 186 (аудит программ
на dev2null.de, конец августа 2026):

> `perr71-stt` (`0.0.0.0:8098`, `/home/inna/perr71-stt/`) работает **без службы systemd**:
> после перезагрузки сервиса не будет.

Значит, `nohup` сделал то же, что `screen` в уроке: сервис продолжал работать спустя недели
после закрытия терминала. Ограничение тоже общее: перезагрузку сервера ни `nohup`, ни
`screen` не переживают.
