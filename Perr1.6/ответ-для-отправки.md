Отдельный учебный проект для этого задания я не разворачивал: весь путь деплоя я уже прошёл
на своём VPS у Netcup в Германии. Это тот же сервер, что в заданиях 1.5, 7.1 и 10.5. Ниже
показано, где сделан каждый шаг.

**Где что сделано.**
- *Проект локально.* Сайт на Flask из задания 10.2: виртуальное окружение,
  `requirements.txt`, запуск и проверка в браузере (скриншоты, 18 тестов).
- *Перенос на сервер и запуск.* Задание 7.1: Python-сервис перенесён на VPS в отдельную
  папку, запущен в своём виртуальном окружении на порту 8098. Код ИИ-ассистента Taris
  переносится на этот же VPS по SCP, без виртуального окружения.
- *Работа в фоне.* Сервис из 7.1 запущен через `nohup` и продолжал работать спустя недели
  после закрытия терминала. Контейнеры Taris Docker перезапускает сам.
- *Docker.* У Taris на VPS свой Dockerfile на `python:3.12-slim`. Образ собирается командой
  `docker build`, бот и сайт запускаются в фоне через `docker compose up -d`, сайт слушает
  порт 8090.
- *Обновление через GitHub.* На том же VPS лежит клон GitHub-репозитория, из которого
  собирается свой образ для n8n: `docker build`, затем контейнер пересоздаётся и
  проверяется.

**Краткое описание.**
Деплой — это перенос программы с моего компьютера на сервер, где она работает постоянно и
доступна другим людям. Локально программа живёт, пока открыт ноутбук, и видна только мне; на
сервере она работает круглосуточно, поэтому ей нужны автозапуск, журнал и защита от сбоев.
FTP просто копирует файлы, причём без шифрования. GitHub хранит историю изменений: на сервер
приходит конкретная проверенная версия, а при ошибке можно откатиться на прошлую. Docker
упаковывает программу вместе со всеми зависимостями, поэтому она одинаково работает на любом
сервере, а перезапуск после сбоя берёт на себя сам. Удобнее всего мне связка GitHub и Docker:
код подключается в контейнер папкой, поэтому обновление — это перенос кода и перезапуск за
секунды, а образ пересобирается только при смене зависимостей. FTP я не использую: вход по
паролю на моём сервере закрыт из-за постоянного перебора паролей, поэтому файлы идут по SCP
поверх SSH с ключом. Самые трудные места были сетевые: n8n в Docker не видел мой сервис на
`127.0.0.1` хоста, это решилось адресом моста Docker. Ещё один урок: аудит показал, что
запущенный через `nohup` сервис переживает закрытие терминала, но не перезагрузку сервера, и
для постоянной работы нужна служба systemd или Docker.
