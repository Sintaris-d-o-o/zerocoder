# Perr1.6 — концепция и план

## Решение пользователя

Как и в Perr1.5, сдаём **отчёт по уже сделанному** и ничего заново не разворачиваем. Все шаги
задания (локальный проект, перенос на сервер, запуск, работа в фоне, Docker, обновление
через GitHub) уже пройдены в рабочих проектах и прошлых заданиях курса.

## Из чего собирается отчёт

| Пункт задания | Источник |
|---|---|
| 1. Проект локально | Perr10.2: Flask, venv, requirements.txt, скриншоты из браузера |
| 2. Перенос на сервер | Taris: `src/` по SCP; Perr7.1: сервис в отдельной папке на VPS |
| 3. Запуск на сервере | Perr7.1 (venv, `0.0.0.0:8098`), Taris в Docker (`0.0.0.0:8090`) |
| 4. Работа в фоне | Perr10.4: systemd вместо screen |
| 5. Docker | Dockerfile и docker-compose Taris на VPS, n8n в Docker (Perr10.5) |
| 6. GitHub | образ task runners из клона репозитория, Forge: `git pull` → перезапуск |

Выдержки из закрытых репозиториев (`sintaris-pl`, `Worksafety-superassistant`,
`sintaris-srv`) копируются в `results/` без паролей, токенов и IP.

Отличия от урока (SCP вместо FTP, systemd вместо screen) в отчёте названы прямо и
обоснованы.

## Проверка

Каждая ссылка ведёт на существующий файл, каждый факт есть в источнике, в выдержках нет
секретов.
