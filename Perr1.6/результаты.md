## Коротко

Задание проводит через весь путь деплоя: проект локально, перенос файлов на сервер, запуск там,
работа в фоне, Docker, обновление через GitHub. Все эти шаги уже пройдены в рабочих проектах

  в браузере.
- **Perr7.1** — Python-сервис, развёрнутый на VPS в своём виртуальном окружении и открытый
  на порту сервера.
- **Perr10.4** — бот и сайт Taris работают на сервере в фоне круглосуточно (systemd вместо
  `screen`), код лежит в GitHub.
- **Perr10.5** — n8n в Docker на домашнем сервере.
- **Taris на VPS в Docker и образ task runners для n8n** — собственные Dockerfile, сборка
  образа, запуск в фоне, обновление. Выдержки из закрытых репозиториев:

## Чем наш вариант отличается от урока и почему

| В уроке | У нас | Зачем |
|---|---|---|
| FTP через FileZilla | SCP (`pscp`) и `git pull` | FTP передаёт пароль и файлы открытым текстом, и на сервере для него нужна отдельная служба. SCP идёт по тому же SSH, что уже открыт, и шифрует всё |
| `screen` | systemd и `restart: unless-stopped` в Docker | `screen` не переживает перезагрузку и не поднимет упавшую программу; systemd и Docker делают это сами |
| `http://IP:порт` | сайт через nginx по адресу с HTTPS (`agents.sintaris.net/...`) | голый порт в интернете — это без шифрования и без защиты; наружу открыт только nginx, приложения слушают порты за ним |
| при каждом обновлении пересобирать образ | код подключается в контейнер папкой, пересборка только при смене зависимостей | обновление занимает секунды, а не минуты сборки |

## Чего нет

- **FTP/FileZilla** не использовался ни разу: везде SCP или Git. Это сознательный выбор,
  причины в таблице выше.
- **`screen -ls`** нет: вместо `screen` работают systemd и Docker, их состояние сохранено
  выводом `systemctl` в [Perr10.4/results/services.txt](../Perr10.4/results/services.txt).
- **Скриншотов терминала** со сборкой образа и списком файлов на сервере нет. Есть сами
  Dockerfile и скрипты, по которым это делается, и записи в журнале выкаток.
  Доснять кадры можно по [demo.md](demo.md).
