# Локальный RAG-консультант по ювелирным изделиям

Учебный проект (задание Perr6.5, курс Zerocoder «Промпт-инжиниринг 2.0»): локальная
RAG-система (Retrieval-Augmented Generation), которая отвечает на вопросы про уход за
ювелирными изделиями, выбор украшений и материалы — опираясь на реальные документы, а не
на «общие знания» модели.

Всё работает **полностью локально, без интернета и без облачных API**: и модель для
генерации ответов, и модель для поиска, и векторные базы — всё считается на вашем
компьютере через [Ollama](https://ollama.com/).

## Как это устроено

1. Документы (`data/Ювелир/*.pdf, *.docx, *.txt`) разбиваются на смысловые кусочки (чанки).
2. Каждый кусочек превращается в вектор (embedding) локальной многоязычной моделью
   `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`.
3. Векторы сохраняются в **две** базы — [FAISS](https://github.com/facebookresearch/faiss)
   и [ChromaDB](https://www.trychroma.com/) — для сравнения (см. [REPORT.md](REPORT.md)).
4. На вопрос пользователя ищутся наиболее похожие по смыслу кусочки текста (retrieval).
5. Кусочки вместе с вопросом отправляются локальной модели **Llama 3.2 (3B)** через Ollama,
   которая формулирует ответ (generation).

## Структура проекта

```
Perr6.5/
├── data/Ювелир/          — исходные документы (уход, выбор изделий, материалы)
├── src/
│   ├── document_loader.py  — загрузка и разбиение документов на чанки
│   ├── vector_store.py     — построение/загрузка индексов FAISS и ChromaDB
│   ├── rag_pipeline.py     — retrieval + генерация ответа
│   └── main.py              — консольный интерфейс (CLI)
├── tests/
│   ├── test_queries.py      — 4 тестовых вопроса из задания, сравнение FAISS/ChromaDB
│   └── test-results.md      — сохранённый лог прогона (готовый пример для проверки)
├── storage/                 — сюда сохраняются векторные индексы (создаётся командой ingest)
├── requirements.txt
├── REPORT.md                 — отчёт: сравнение FAISS и ChromaDB
└── README.md
```

## Установка

### 1. Ollama и модель

Установите [Ollama](https://ollama.com/download) (в этом проекте использовалась версия для
Windows, установленная через `winget install --id Ollama.Ollama`) и скачайте модель:

```bash
ollama pull llama3.2:3b
```

Ollama работает как фоновая служба на `localhost:11434` — после установки она обычно
запускается автоматически.

### 2. Python-окружение

Требуется Python 3.10+.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

## Запуск

### Построить векторные базы (один раз, после изменения документов)

```bash
python -m src.vector_store
```

Это создаст `storage/faiss_index/` и `storage/chroma_db/`.

### Задать вопрос

```bash
python -m src.main "Как ухаживать за золотыми изделиями?"
python -m src.main "Как чистить серебро?" --backend chroma
```

Флаг `--backend` переключает базу поиска: `faiss` (по умолчанию) или `chroma`.

### Прогнать тестовые вопросы из задания

```bash
python -m tests.test_queries
```

Сохранит результаты (вопрос, ответ, использованные фрагменты, время ответа для обеих баз)
в `tests/test-results.md`.

Быстрые проверки на здравый смысл можно также запустить через pytest:

```bash
pytest tests/test_queries.py
```

## Заметка про качество генерации маленькой моделью

При первых прогонах модель `llama3.2:3b` на открытых/обобщающих вопросах иногда уходила в
бесконечный повтор одного и того же списка слов (зацикливание генерации). Чтобы это
исключить, в `src/rag_pipeline.py` заданы `num_predict=512` (жёсткий потолок длины ответа) и
`repeat_penalty=1.3` (штраф за повтор токенов). Это решает проблему, но иногда даёт побочный
эффект — единичные "склеенные" слова на стыке кириллицы и латиницы (например `ос freshить`
вместо `освежить`) в ответах. Ответы при этом остаются полностью читаемыми и корректными по
содержанию — все использованные фрагменты и ответы можно проверить в
`tests/test-results.md`.

## Почему именно Llama 3.2 (3B)

В задании допускается «Llama3 или аналог». Полная Llama 3 (8B) на процессоре без видеокарты
отвечает по 1–3 минуты на вопрос; Llama 3.2 (3B) — модель того же семейства Meta Llama, но
лёгкая и быстрая (секунды на ответ) — удобнее для разработки и демонстрации, при этом
качество ответов на этой предметной области осталось достаточным (см. примеры в
`tests/test-results.md`).
