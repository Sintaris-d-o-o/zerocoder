# Задание 10.7 — как показать работу

## Запуск

```bash
cd Perr10.7
pip install -r requirements.txt
streamlit run app.py
```

Откроется `http://localhost:8501`. Ключ берётся из `.env` в корне репозитория
(`OPENAI_API_KEY`), модель — `gpt-4o-mini`, её можно сменить в боковой панели или
переменной `PRESCORE_MODEL`.

Публичного адреса нет: сервис локальный. Если нужно дать ссылку проверяющему — скажите,
подниму рядом с n8n на SintAItion, там уже есть и nginx, и сертификаты.

## Показать за три минуты

1. Выбрать вакансию «Специалист по регуляторным вопросам (MDR/IVDR)» — она уже в списке.
2. Загрузить `data/resumes/profile-regulatory.pdf`, ввести имя, нажать «Оценить».
   Через несколько секунд — **76 из 100, подходит**, сильные стороны, чего не хватает.
3. Тем же порядком загрузить `data/resumes/offtopic-frontend.pdf` — **10 из 100,
   не подходит**, и модель прямо пишет, чего именно нет.
4. Раскрыть «Как посчитана формула» — видно, какие требования вакансии засчитаны,
   какие нет, и совпало ли семейство должностей.
5. Внизу страницы — история: оба кандидата в одной таблице, сравнение и выгрузка.

Показательно подвигать ползунки весов: у профильного кандидата балл почти не
меняется, у смежного — заметно. Это и есть смысл настройки под конкретную вакансию.

## Те же три резюме одной командой

```bash
python run_batch.py                 # все резюме по первой вакансии
python run_batch.py --vacancy 2     # по вакансии инженера по качеству
python run_batch.py --dry-run       # без модели, только формула
```

`--dry-run` полезен, чтобы показать вклад формулы отдельно: она считается без модели
и даёт те же числа при каждом запуске.

Готовый вывод лежит в `results/прогон-3-резюме.txt`.

Код `app.py` и файл `results/прогон-3-резюме.txt` уже в папке задания.

## Свои данные

**Своя вакансия:** выбрать в списке «Своя вакансия» и вставить текст.

**Свои резюме:** положить PDF в `data/resumes/` — `run_batch.py` подхватит все файлы
из папки. Сгенерировать новые обезличенные резюме: отредактировать словарь `RESUMES`
в `make_resumes.py` и запустить `python make_resumes.py`.

## Если что-то не работает

| Признак | Что проверить |
|---|---|
| «В .env нет OPENAI_API_KEY» | ключ должен лежать в `.env` в корне репозитория или рядом с `app.py` |
| Пустой текст из PDF | резюме — картинка, а не текст; `pdfplumber` распознаванием не занимается |
| «Модель вернула не JSON» | формула всё равно посчитана; нажать «Оценить» ещё раз |
| Баллы кажутся заниженными | посмотреть «Не подтверждено» в разборе формулы: скорее всего резюме и вакансия говорят о том же разными словами — тогда стоит добавить пару в `SYNONYMS` в `normalize.py` |
| История не обновляется | `history.json` рядом с `app.py`; кнопка «Очистить историю» удаляет файл |

Тесты: `python -m pytest tests/ -q` — 38 штук, модель для них не нужна.
