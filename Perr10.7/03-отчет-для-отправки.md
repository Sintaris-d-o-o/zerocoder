## Краткое описание

Сервис прескоринга кандидатов сделан на Streamlit, анализ резюме — через
**`gpt-4o-mini`** (модель и её выбор вынесены в `.env`/боковую панель, можно
сменить без правки кода). Итоговый балл — взвешенная смесь: **55% оценка
модели, 45% формула** без модели (доля подтверждённых требований вакансии,
опыт в годах, мягкие навыки, плюс поправка ±10 баллов за совпадение семейства
должностей). Веса трёх групп критериев (hard skills, опыт, soft skills)
настраиваются ползунками в интерфейсе и автоматически нормируются к 100%.

Главная сложность была не в вызове модели, а в подготовке текста к ней: PDF
отдаёт переносы по слогам вперемешку с переносами по границе страницы, и если
сначала склеивать строки, а потом дефисы, слово остаётся разорванным —
пришлось зафиксировать порядок операций тестами. Вторая сложность — простое
совпадение слов длиннее 4 букв засчитывало служебные слова вакансии
(«требования», «обязанности») как совпавшие навыки у любого резюме; помогли
стоп-слова и словарь синонимов. Отдельно проверено, что строгий формат ответа
модели (`response_format=json_object`) нужен реже, чем «ремонт» JSON, но
ремонт всё равно оставлен как запасной путь — не все модели одинаково хорошо
держат формат.

Из дальнейших улучшений: вынести сервис на публичный адрес (сейчас работает
локально через `streamlit run app.py`, но инфраструктура для публикации уже
есть на другом сервере проекта), и сравнить оценки нескольких разных моделей
на одном и том же наборе резюме — это было опциональным пунктом задания.

## Какие скриншоты нужны

Кладите в `Perr10.7/results/screenshots/`. Сервис запускается локально:

```bash
cd Perr10.7
pip install -r requirements.txt
streamlit run app.py
```

Откроется `http://localhost:8501`.

|---|---|---|---|
| 1 | `0-interface.png` | Главный экран: выбранная вакансия «Специалист по регуляторным вопросам», загруженный `data/resumes/profile-regulatory.pdf`, поле имени заполнено — до нажатия «Оценить» | — |

| 3 | `2-analysis-offtopic.png` | Результат по неподходящему кандидату (`offtopic-frontend.pdf`): балл 10 | тем же порядком с другим файлом — необязательный, но задание просит «пример анализа», а разница между двумя кандидатами показательнее одного |
| 4 | `3-formula-breakdown.png` | Раскрытый блок «Как посчитана формула» — видно, какие требования засчитаны | клик по блоку на экране результата |
| 5 | `4-history-table.png` | Таблица истории внизу страницы с 2–3 оценёнными кандидатами | появится после нескольких оценок подряд |

Пункты 1–2 и 5 — обязательный минимум по заданию (интерфейс, пример анализа,
история). Пункты 3–4 — из `demo.md`, делают отчёт нагляднее, но не обязательны.

Быстрее всего получить сразу и данные для истории, и протокол — прогнать
`python run_batch.py`, а затем открыть `app.py` и оценить те же резюме через
интерфейс (быстрый вызов формулы даже без ожидания модели — флаг `--dry-run`
у `run_batch.py`, но для скриншотов интерфейса нужен именно `app.py`).
