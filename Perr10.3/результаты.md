# Задание 10.3 — что сделано и какие результаты

## Статус

**Код готов и проверен, генерация ждёт ключа.** Написаны генератор видео и скрипт проверки
статуса, 26 тестов проходят. Для получения самого видео нужен ключ Proxy API с пополненным
балансом — как его завести, описано в конце.

## Что сделано

Генератор коротких роликов по теме проекта: управление сертификатами медицинских изделий.

Два файла, как требует задание:

- [video_generator.py](video_generator.py) — запускает генерацию, ждёт с прогресс-баром,
  скачивает готовый MP4;
- [test.py](test.py) — проверяет статус.

## Почему два файла, а не один

Задание прямо требует проверять статус через `test.py`, и на то есть практическая причина.
Генерация видео занимает минуты: задача сначала стоит в очереди, потом обрабатывается, потом
результат рендерится в файл. Держать окно терминала открытым всё это время неудобно, а при
обрыве связи результат теряется.

Разделение решает проблему: генерацию запустили, окно закрыли, позже отдельной командой
посмотрели статус и забрали файл.

`test.py` умеет четыре вещи:

| Команда | Что делает |
|---|---|
| `python test.py` | проверяет доступ: виден ли ключ, отвечает ли сервис. Денег не тратит |
| `python test.py <id>` | показывает статус конкретной задачи |
| `python test.py --watch <id>` | следит до завершения и скачивает результат |
| `python test.py --list` | показывает последние задачи |

## Собственные промпты

Задание прямо запрещает брать пример эксперта с чашкой кофе. Написаны три собственных, по теме
проекта:

| Ключ | Что в кадре |
|---|---|
| `certificates` | документы с печатями на светлом столе складываются в ровную стопку, медленный наезд камеры |
| `lab` | лаборатория контроля качества: рука в перчатке ставит прибор на стенд, индикаторы меняют цвет с янтарного на зелёный |
| `dashboard` | панель контроля сроков в тёмном пространстве: карточки меняют статус с красного на зелёный |

Промпты написаны по-английски намеренно. Модели генерации видео обучены преимущественно на
английских описаниях и понимают их точнее — это тот самый приём «перевести на более ресурсный
язык», о котором говорил урок 9.1.

## Что сделано сверх урока

1. **Прогресс-бар в терминале.** Задание требует скриншот с прогрессом, поэтому в одну строку
   выводятся полоса, процент, статус и прошедшее время.
2. **Запись пути статусов.** Рядом с видео сохраняется файл с промптом, моделью, длительностью
   и полной цепочкой статусов. По нему видно, сколько задача простояла в очереди и сколько
   обрабатывалась.
3. **Понятные ошибки.** Отдельно объясняются нехватка средств на балансе, неверный ключ,
   неправильный адрес сервиса и превышение частоты запросов.
4. **Потолок ожидания** 15 минут: застрявшая в очереди задача не заставит скрипт висеть вечно.
5. **Режим `--dry-run`** — показывает запрос, не отправляя его.
6. **Тесты без обращения к сервису.** Генерация видео — самая дорогая операция модуля, поэтому
   вся логика проверяется на подменённом клиенте.

## Что нужно, чтобы получить видео

Нужен ключ Proxy API. В проектах его нет.

1. Зарегистрироваться на сервисе Proxy API.
2. Пополнить баланс. Генерация видео — самая дорогая операция из трёх заданий модуля,
   один четырёхсекундный ролик стоит заметно дороже картинки.
3. Раздел «Ключи API» → «Создать новый ключ API». **Ключ показывается один раз**, сохранить
   сразу.
4. Положить строку `PROXYAPI_KEY=...` в файл `.env` в корне репозитория.

После этого:

```powershell
cd Perr10.3
python test.py                       # проверить доступ, бесплатно
python video_generator.py --dry-run  # посмотреть запрос, бесплатно
python video_generator.py            # сгенерировать ролик на 4 секунды
```

Видео и файл с параметрами прогона сохранятся в `results/`, и я добавлю скриншоты в отчёт.
