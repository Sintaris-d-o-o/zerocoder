## Почему RouterAI, а не Proxy API

Ключа Proxy API не было, а аккаунт RouterAI уже есть. Сервисы устроены одинаково: оба дают
единый API к моделям разных компаний. На RouterAI доступны те же модели, включая Sora из урока:

| Модель | Кто сделал |
|---|---|
| `openai/sora-2-pro` | OpenAI — та самая модель из урока |
| `google/veo-3.1`, `veo-3.1-fast`, `veo-3.1-lite` | Google |
| `kwaivgi/kling-v3.0-pro`, `kling-v3.0-std`, `kling-video-o1` | Kuaishou |

Разница только в интерфейсе. У Proxy API вызов идёт через стандартный клиент `openai` с другим
адресом сервера. У RouterAI — свой REST: запрос на `/api/v1/videos`, в ответ приходит
идентификатор задачи и адрес для опроса, готовое видео скачивается по ссылке из ответа.

В коде поддержаны оба сервиса. Какой использовать, скрипт решает сам по тому, какой ключ лежит
в `.env`; выбрать вручную можно переменной `VIDEO_PROVIDER` или ключом `--provider`.

## Почему два файла, а не один

Задание требует проверять статус через `test.py`, и на то есть практическая причина.
Генерация занимает от 30 секунд до нескольких минут, а стоит денег. Держать окно открытым
всё это время неудобно, а при обрыве связи оплаченный результат теряется.

`test.py` умеет четыре вещи:

| Команда | Что делает |
|---|---|
| `python test.py` | проверяет доступ и **остаток на счету**; денег не тратит |
| `python test.py <id>` | показывает статус задачи и подсказывает следующую команду |
| `python test.py --watch <id>` | следит до готовности и скачивает |
| `python test.py --download <id>` | скачивает уже готовое видео |

Этим же скриптом был забран первый ролик, сгенерированный до того, как код был дописан:
задача осталась на сервисе, и оплаченный результат не пропал.

## Что сделано сверх задания

1. **Два сервиса в одном коде.** Выбор по наличию ключа, с возможностью указать вручную.
2. **Контроль расходов.** Команда `--check` показывает остаток на счету и считает, на сколько
   роликов его хватит. Генерация видео дорогая: ролик на 4 секунды стоил от 22 до 44 кредитов
   в зависимости от модели.
3. **Прогресс-бар** с полосой, процентом, статусом и временем — задание просит скриншот с ним.
4. **Проверка, что скачался именно MP4.** Файл проверяется по сигнатуре. Если вместо видео
   придёт страница с ошибкой, это будет видно сразу, а не при попытке открыть файл.
5. **Запись параметров прогона** рядом с видео: промпт, модель, длительность, цепочка статусов,
   стоимость. По ней видно, сколько задача простояла в очереди.
6. **Скрипт скриншота терминала.** Прогресс-бар перерисовывает одну строку, поэтому в файле
   лога он лежит одной длинной строкой; скрипт разворачивает её обратно по шагам.
7. **Потолок ожидания** 15 минут — застрявшая задача не подвесит скрипт.

## Что проверено тестами

| Проверка | Зачем |
|---|---|
| В запрос уходят нужные параметры | включая длительность 4 секунды из задания |
| Сервис выбирается по ключу в `.env` | и ручной выбор сильнее автоматического |
| Цикл проходит все статусы | `pending` → `processing` → `completed` |
| Неудачные статусы дают ошибку | `failed`, `cancelled`, `rejected` |
| Неизвестный статус не проглатывается | иначе скрипт молча зациклится |
| Срабатывает потолок ожидания | защита от застрявшей задачи |
| Готовая задача без ссылки на файл — ошибка | а не тихий выход |
| Скачанное проверяется на сигнатуру MP4 | страница с ошибкой не станет «видео» |
| Пустой файл отвергается | вместо сохранения нулевого размера |
| Имя файла безопасно для Windows | двоеточие увело бы запись в скрытый поток |
| Ошибки объясняются словами | нехватка средств, неверный ключ, неверные параметры |

| Остаток на счету не роняет работу | если сервис не ответил, генерация всё равно идёт |
| Все четыре режима `test.py` | включая слежение со скачиванием |

## Честные оговорки

1. **Сервис заменён** с Proxy API на RouterAI. Урок это разрешает, способ из урока в коде
   сохранён и включается ключом `PROXYAPI_KEY`, но на реальном сервисе не проверялся —
   ключа нет.
2. **Модель другая.** Ролик сделан на `google/veo-3.1-lite`, а не на Sora. Причина
   практическая: Sora на этом сервисе заметно дороже, а на счету оставалось 65 кредитов.
   Код от модели не зависит, она меняется ключом `--model`.
3. **Прогресс-бар показывает стадию, а не проценты.** Сервис процент готовности не сообщает,
   поэтому полоса отражает стадию: очередь — четверть, готово — целиком.
