# Задание 1.5 — отчёт для проверяющего

## Как выполнено

Этот базовый этап у меня пройден раньше и в более полном виде. Для своего проекта
Taris (ИИ-ассистент: Telegram-бот и веб-приложение) я арендую VPS в Германии, работаю
с ним по SSH и запускаю на нём Python. Без этого не получились бы следующие задания
курса: 7.1 (сервис распознавания речи на сервере), 10.4 (службы Taris на сервере),
10.5 и 10.6 (публичный адрес для n8n, запуск скрипта с VPS). Поэтому отдельный учебный
сервер я не создавал, а подтверждаю пункты задания результатами этих работ.

## 1. Параметры сервера

| Параметр | Выбор | Почему |
|---|---|---|
| Тип проекта | рабочий проект: веб-приложение и Telegram-бот, n8n, публичный вход для домашнего сервера | сервер нужен постоянно и должен быть виден из интернета |
| Локация | Германия | пользователи в Европе — меньше задержка; данные остаются в ЕС |
| ОС | Linux | Docker, nginx, PostgreSQL, Python ставятся стандартно |
| Память | около 8 ГБ | замерено: веб-приложение, бот, n8n, PostgreSQL, nginx и Docker вместе занимают около 2,3 ГБ без локальной нейросети |
| Нейросеть | через API, не на сервере | на VPS нет видеокарты; локальная модель потребовала бы 8–10 ГБ памяти только под себя (расчёт в задании 9.2), поэтому тяжёлые модели работают на отдельном домашнем сервере |

Логика урока «под задачу, а не с запасом»: для учебного `hello.py` хватило бы самого
дешёвого тарифа (1 ядро, 1 ГБ). Наш сервер больше, потому что задача больше, и размер
подобран по замерам, а не «на всякий случай». При этом без локальной модели сам Taris на
VPS занимает всего около 120 МБ (два контейнера: 25 и 98 МБ).

**Чего нет.** Скриншотов ровно в том виде, как просит задание (окно входа по SSH,
вывод `apt update` / `apt upgrade`, `python3 --version`, запуск `hello.py`), у меня
нет: эти шаги я проходил при первоначальной настройке сервера и не снимал. Новые снимки
делать не стал, чтобы не трогать рабочий сервер: `apt upgrade` обновляет все программы
сразу и может перезапустить службы, от которых зависят живые сервисы. Вместо снимков —
сохранённые выводы команд из заданий выше.

## Краткое описание

Я использую VPS в Германии для рабочего проекта — ИИ-ассистента Taris: на сервере
работают веб-приложение, Telegram-бот, n8n и публичный вход для моего домашнего сервера
с нейросетями. Конфигурация — Linux и около 8 ГБ памяти: по замерам весь набор служб без
локальной нейросети занимает около 2,3 ГБ, а нейросети вынесены на домашний сервер или
работают через API, потому что на VPS нет видеокарты. Самым сложным при работе с
сервером оказалось не само подключение, а сети внутри него: n8n в Docker не видел службу
на `127.0.0.1` хоста, и пришлось разбираться с адресами контейнеров. Второй урок —
осторожность: рабочие службы нельзя задевать, поэтому учебные сервисы я запускал под
отдельным пользователем, в отдельной папке и на свободном порту. SSH нужен, чтобы
безопасно управлять сервером из своего терминала: соединение шифруется, вместо пароля
можно использовать ключ, а через SSH-туннель можно даже вывести в интернет домашний
сервер, который сам снаружи не виден. VPS лучше локального сервера тем, что работает
круглосуточно, имеет постоянный публичный адрес и не зависит от домашнего интернета и
электричества. Именно поэтому мой домашний сервер с нейросетями доступен пользователям
только через VPS: тот принимает запросы из интернета и передаёт их домой по туннелю.
