Отдельный учебный сервер я не заводил. Для своего проекта, ИИ-ассистента Taris, я арендую
VPS у Netcup в Германии и работаю на нём по SSH. Это тот же сервер, на котором я выполнял
задания 7.1 (сервис распознавания речи) и 10.5 (запуск скрипта `main.py` «с чужой машины»).
Ниже показано, где пройден каждый шаг этого задания.

**Параметры сервера.**

| Параметр | Значение | Почему |
|---|---|---|
| Тип проекта | рабочий сервер: сайт и Telegram-бот ассистента, n8n, почта, базы данных | сервер нужен постоянно и должен быть виден из интернета |
| Локация | Германия | пользователи в Европе, данные остаются в ЕС |
| ОС | Ubuntu 24.04 LTS | долгая поддержка, Docker, nginx, PostgreSQL и Python ставятся стандартно |
| CPU / RAM / диск | 6 ядер / 7,7 ГБ / 504 ГБ | все службы вместе занимают около 2,3–2,7 ГБ памяти, а файлы Nextcloud и образы Docker — сотни гигабайт |
| Нейросеть | не на этом сервере | видеокарты на VPS нет, а одна локальная модель заняла бы 7,7 ГБ памяти (замер в задании 9.2); модели работают на домашнем сервере или через API |

**Где пройдены шаги.**
- *SSH:* вход только по ключу; для root вход запрещён.
- *Обновления:* включены автоматические обновления безопасности (`unattended-upgrades`).
  Регулярный аудит показывает, сколько обновлений ждёт установки и нужна ли перезагрузка.
- *Python на сервере:* в задании 7.1 на этом VPS создано виртуальное окружение Python и
  запущен свой сервис на порту 8098. Аудит сервера спустя недели показал, что сервис
  продолжает работать. В задании 10.5 с этого VPS запущен `main.py`: ответ `200 ✔ успех`
  за 3,3 секунды, пост появился в канале.
- *Ошибки и их исправление:* в задании 7.1 на сервере найдено и исправлено семь проблем,
  от занятого порта до «зависания» сервиса на длинном файле.

**Краткое описание.**
Для задания я использовал свой рабочий VPS у Netcup в Германии с Ubuntu 24.04: на нём
работают сайт и бот моего ИИ-ассистента, n8n, почта и базы данных. Конфигурацию (6 ядер,
7,7 ГБ памяти) я подбирал под этот набор служб по замерам: им нужно около 2,7 ГБ, а
нейросети на сервер не ставлю, потому что одна модель заняла бы ещё 7,7 ГБ. Самым сложным
в подключении оказалась безопасность. По логам на сервер шёл перебор паролей с адресов из
десятков стран (8 766 неудачных попыток), поэтому я закрыл вход по паролю и оставил только вход по
ключу. Оказалось, что настройку SSH нужно менять в нескольких файлах сразу, потому что
действует первая найденная. А три неудачные попытки ввести пароль однажды заблокировали
мой собственный домашний адрес. SSH нужен, чтобы управлять сервером из своего терминала
через зашифрованное соединение: команды и данные для входа никто не перехватит, а вместо
пароля можно использовать ключ. VPS лучше локального сервера тем, что работает
круглосуточно, имеет постоянный публичный адрес и не зависит от домашнего интернета и
электричества.
