# Perr1.5 — концепция и план

## Решение пользователя

Сдаём **отчёт по уже сделанному**, а не учебный прогон. Все действия задания (выбрать и
завести VPS, зайти по SSH, обновить систему, запустить Python на сервере) в SINTARIS уже
выполнены в рабочем режиме и задокументированы. Повторять их на новом платном сервере или
трогать рабочие серверы ради `hello.py` смысла нет.

Рассматривались и отклонены два варианта:
- **новый минимальный VPS** у Timeweb/Beget (первая версия этой концепции, коммит `00e1201`):
  лишние деньги и время на то, что уже умеем;
- **живой прогон на si-node** (коммит `2a8dbf1`): `apt upgrade` на работающем VPN-узле
  рискует перезапустить службы ради учебного скриншота.

## Из чего собирается отчёт

| Пункт задания | Источник |
|---|---|
| 1–2. Параметры и создание VPS | si-node (NEOSERV, Словения, 1 ядро / 1 ГБ / 14 ГБ, Ubuntu 26.04), заведён 19.08.2026 под VPN-узел. Документация в закрытом `sintaris-srv`, выдержки скопированы в `results/` |
| 3. SSH | журнал первого сеанса на si-node, Perr7.1 (VPS dev2null.de), Perr10.4 (сервер SintAItion) |
| 4. `apt update/upgrade`, Python | автообновления (unattended-upgrades) с первого сеанса; Python 3 работает в Perr7.1 и Perr10.4 |
| 5–6. Python-файл на сервере | Perr7.1 `stt_service.py` (развёрнут по SSH, 6 тестов, 7 исправленных проблем), Perr10.4 `bot_web.py` и `telegram_menu_bot.py` (круглосуточно) |

## Что получится

- `результаты.md` — таблица «пункт задания → где выполнено → доказательство» и сверка.
- `ответ-для-отправки.md` — готовое описание на 5–10 предложений и список приложений.
- `results/выдержки-из-журнала-серверов.md` — строки из закрытой документации серверов,
  без секретов, чтобы проверяющему хватало открытой папки.
- `demo.md` — где что смотреть и, на случай если проверяющий потребует живые кадры,
  5-минутный набор команд для владельца.

## Тестирование

Код не пишется, поэтому проверяем отчёт: каждая ссылка ведёт на существующий файл, каждый
факт в отчёте есть в источнике, в выдержках нет паролей и ключей.
