# Задание 1.5 — концепция и план

## Что делаем и зачем

Арендуем у хостинг-провайдера маленький виртуальный сервер (VPS) — «компьютер в
дата-центре», который работает круглосуточно и доступен из интернета.
Подключаемся к нему из терминала по SSH, обновляем систему и запускаем первый
скрипт на Python.

## Два шага, которые могу сделать только вы

1. **Регистрация у провайдера и оплата.** Это ваш аккаунт и ваши деньги: я не
   могу зарегистрироваться или ввести данные карты за вас.
2. **Скриншот панели провайдера с IP-адресом.** Я не вижу ваш браузер.

Всё остальное (SSH, обновление, Python, файл, запуск, скриншоты терминала,
описание) могу сделать я, как в задании 1.4.

## Решение 1: новый сервер или уже существующий

У вас уже есть рабочий VPS (`dev2null.de`) — на нём живые цепочки n8n.
Использовать его для задания **не рекомендую**: задание требует `apt upgrade`, а
это обновление всех программ сервера. На рабочем сервере оно может перезапустить
службы или поменять версии, от которых зависят цепочки. Учебное задание не должно
рисковать рабочим контуром.

**Рекомендую новый отдельный минимальный VPS** — это и есть суть задания
(«создай VPS»). После сдачи его можно удалить, чтобы не платить.

## Параметры сервера (пункт 1 задания)

| Параметр | Выбор | Почему |
|---|---|---|
| Тип проекта | **тестовый запуск** | задача — запустить один короткий скрипт, ни сайта, ни бота пока нет |
| Провайдер | **Timeweb Cloud** (или Beget — на ваш выбор) | оба названы в уроке, оплата посуточно/помесячно, сервер создаётся за минуты |
| ОС | **Ubuntu 24.04 LTS** | самая распространённая, Python 3 уже в комплекте, LTS — долгая поддержка |
| CPU | **1 ядро** | скрипт из двух строк выполняется за доли секунды |
| RAM | **1 ГБ** | Ubuntu с запасом хватает 512 МБ–1 ГБ, `apt upgrade` на 1 ГБ проходит спокойно |
| Диск | **минимальный в тарифе** (обычно 10–15 ГБ) | система занимает 3–4 ГБ, наш файл — байты |
| Локация | **Европа** (Франкфурт или Амстердам) | ближе к вам — меньше задержка в SSH-терминале; если нет — любая доступная |

Логика урока «под задачу, а не с запасом»: для тестового запуска берём самый
дешёвый тариф. Если потом здесь будет бот — увеличить ресурсы можно за пару
кликов, не пересоздавая сервер.

## Как будет устроено подключение

- Пароль сервера кладётся **только в `.env`** (`VPS15_HOST`, `VPS15_USER`,
  `VPS15_PASSWORD`) — не в документы и не в коммиты.
- Я подключаюсь обычной командой `ssh root@IP`, как в задании. Ввести пароль
  руками в моём терминале нельзя, поэтому `ssh` получает его из `.env` через
  стандартный механизм OpenSSH «спросить пароль у программы» (`SSH_ASKPASS`) —
  пароль нигде не печатается.
- **Про nano.** nano — экранный редактор, в нём печатают руками; мой терминал
  так не умеет. Варианты: вы делаете этот шаг сами (около минуты, команды дам),
  или я создаю тот же файл командой терминала и честно пишу об этом в отчёте.
  Рекомендую первый — задание явно требует nano.

## План реализации

1. **Вы:** регистрируетесь, создаёте VPS с параметрами из таблицы, делаете
   скриншот панели с IP, кладёте IP и пароль в `.env` (шаблон подготовлю).
2. **Я:** первое подключение `ssh root@IP`, подтверждение отпечатка сервера
   («yes»), проверки `whoami`, `hostname`, `uname -a`.
3. **Я:** `apt update`, `apt upgrade -y`, `python3 --version`.
4. **Вы или я (см. «Про nano»):** файл `hello.py` с двумя строками `print`.
5. **Я:** `cat hello.py`, `python3 hello.py`.
6. **Я:** весь вывод сохраняю в `протокол/`, делаю из него скриншоты терминала
   (как в 1.4), пишу описание, `demo.md`, `результаты.md`.

## План тестирования

- `ssh` подключается, `whoami` отвечает `root`, `hostname` — имя нового сервера.
- `apt update` заканчивается без ошибок, `apt upgrade` — без ошибок; если
  попросит перезагрузку — перезагружаем и подключаемся заново.
- `python3 --version` показывает версию 3.x.
- `python3 hello.py` выводит ровно две строки: `Hello, World!` и
  `My first server!`.

## План демонстрации

В папке `Perr1.5/`: скриншот панели (ваш), четыре скриншота терминала,
протоколы команд, `hello.py`, `demo.md`, `результаты.md` с кратким описанием
(5–10 предложений) и сверкой с заданием. Пароль и IP в отчёте не публикуются —
IP на скриншоте панели при желании можно закрасить.
