# N3 — Концепция реализации ИИ-ассистента для обработки вакансий в n8n

## 1. Обзор системы

### Назначение
Автоматизированный HR-ассистент на базе n8n и LLM, который без участия человека обрабатывает входящие письма от кандидатов, анализирует резюме, сопоставляет их с открытыми вакансиями и отправляет персонализированные ответы.

### Ключевые возможности
- Автоматическое получение писем и извлечение вложений
- Парсинг PDF-резюме и структурирование данных
- ИИ-мэтчинг кандидата с базой вакансий по многофакторной системе баллов
- Автоматическая отправка письма-приглашения или письма-отказа
- Сохранение профиля кандидата и результатов мэтчинга в БД
- Защита от дублирования кандидатов
- Защита от манипуляций через имитацию «человеческого» времени обработки

---

## 2. Архитектура workflow

```
[Gmail Trigger]
      │
      ▼
[Extract from PDF]          ← вложение из письма
      │
      ▼
[Information Extractor]     ← LLM → структурированный JSON кандидата
      │
      ├──────────────────────────────────────────────┐
      ▼                                              ▼
[AI Agent: Matching]                     [Google Sheets: Append Row]
  ├─ OpenAI Chat Model (GPT-4)               ← сохранение профиля кандидата
  └─ Google Sheets Tool (вакансии)
      │
      ▼
[Structured Output Parser]
      │
      ▼
[If: score >= 60?]
  ├── TRUE  → [Wait] → [Gmail: Send Invite]  → [Gmail: Add Label]
  └── FALSE → [Wait] → [Gmail: Send Reject]  → [Gmail: Add Label]
```

## 3. Описание компонентов

### 3.1 Gmail Trigger — получение писем
**Нода:** `Gmail → On message received`

| Параметр | Значение |
|---|---|
| Poll times | каждую минуту (или по расписанию) |
| Event | Message received |
| Simplify | выключить (нужны полные данные) |
| Download Attachments | включить |
| Filter: Read Status | Unread |

**Назначение:** триггер запускает workflow при поступлении нового письма. Обязательно скачивает вложения (PDF с резюме).

---

### 3.2 Extract from PDF — конвертация резюме
**Нода:** `Extract from PDF`

Извлекает текст из бинарного PDF-вложения и передаёт его далее в виде plaintext-строки. Входные данные — `binary` из Gmail, выход — поле `text`.

---

### 3.3 Information Extractor — структурирование данных
**Нода:** `Information Extractor` + `OpenAI Chat Model`

Принимает сырой текст резюме и возвращает строго типизированный JSON-объект кандидата.

#### Схема выходных данных (атрибуты)

| Ключ | Тип | Обязательный | Описание |
|---|---|---|---|
| `full_name` | String | ✅ | Полное имя |
| `sex` | String | — | Пол (муж/жен) |
| `birth_date` | Date | ✅ | Дата рождения |
| `contact_phone` | String | ✅ | Телефон |
| `email` | String | ✅ | Email |
| `country` | String | — | Страна проживания |
| `city` | String | — | Город проживания |
| `citizenship` | String | — | Гражданство |
| `position` | String | ✅ | Желаемая должность |
| `employment` | String | — | Тип занятости |
| `experience` | Number | — | Опыт в годах |
| `skills` | Array | — | Список навыков |
| `salary` | Number | — | Желаемая зарплата |

#### Настройки модели
- Режим: `From Attribute Descriptions`
- Модель: `GPT-4o` или `GPT-4`
- Temperature: `0.1` (высокая точность структурирования)

---

### 3.4 AI Agent — ИИ-мэтчинг
**Нода:** `AI Agent` + `OpenAI Chat Model (GPT-4)` + `Google Sheets Tool`

Основной модуль системы. Агент получает профиль кандидата, читает все вакансии из Google Sheets и возвращает структурированный JSON с результатами сопоставления.

#### Настройки агента
- **Source for Prompt:** Define Below
- **Prompt:** `{{ $json.output }}` (JSON-объект кандидата)
- **Require Specific Output Format:** включено
- **Response Format (модель):** JSON
- **Temperature:** `0.3`

#### Системный промпт (логика мэтчинга)

Агент получает задачу «матчинг-агента вакансий» со следующими правилами:

**Нормализация:**
- Текст приводится к lower-case
- Выполняется транслитерация (frontend ~ фронтенд)
- Синонимы объединяются (js/javascript, ts/typescript, react/react.js и т.д.)

**Семейства должностей:**
| Семья | Примеры ключевых слов |
|---|---|
| frontend | frontend, react developer, ui engineer, web developer |
| backend | backend, nodejs backend, java developer |
| fullstack | fullstack, mern, node + react |
| mobile | ios, android, react native |
| devops | devops, sre, platform engineer |
| data | data engineer, ml engineer |
| qa | qa, test engineer, тестировщик |

**Уровни (сениорность по опыту):**
- 0–1 лет → Junior
- 2–4 лет → Middle
- 5–8 лет → Senior
- 9+ лет → Lead/Principal

#### Система баллов (0–100)

| Критерий | Макс. баллов |
|---|---|
| Совпадение роли / семейства должностей | 40 |
| Скилл-оверлап | 30 |
| Опыт / уровень | 10 |
| Тип занятости | 5 |
| Локация / формат работы | 5 |
| Зарплатные ожидания | 5 |
| Прочие сигналы (язык, домен) | 5 |

**Пороговые значения:**
- `score ≥ 60` → **matches** (подходит, отправляем приглашение)
- `45 ≤ score < 60` → **near_misses** (почти подходит, сохраняем)
- `score < 45` → **notable_non_matches** (не подходит, сохраняем)

### 3.6 Google Sheets — база данных

Используются два листа в одном документе:

#### Лист «Вакансии» (источник для мэтчинга)
| Должность | Описание | Требования | Зарплата |
|---|---|---|---|
| Frontend Developer | React, Redux, TypeScript... | 5+ лет опыта | 150 000 – 200 000 |

#### Лист «Кандидаты» (результаты)
| Имя | Позиция | Навыки | Опыт | Уровень | Город | Страна | Зарплата | Результат |
|---|---|---|---|---|---|---|---|---|

**Формула маппинга поля «Навыки»:**
```javascript
{{ $json.output.candidate_summary.normalized_skills.join(', ') }}
```

**Формула маппинга поля «Результат»:**
```javascript
{{ 'id: ' + $json.output.matches
  .filter(item => item.score > 60)
  .map(item => `${item.row_number}\ntitle: ${item.title}\nscore: ${item.score}\nrisks: ${item.risks.join(', ')}`)
  .join(', ')
}}
```

---

### 3.7 Ветвление логики ответа (If Node)

**Условие:**
```javascript
{{ $json.output.matches.filter(item => item.score > 60).length >= 1 }}
```

- `TRUE` → есть подходящие вакансии → отправляем приглашение
- `FALSE` → вакансий нет → отправляем отказ

### 3.9 Gmail Add Label — маркировка писем

После отправки ответа письмо в ящике помечается меткой для визуальной идентификации.

- Метка: `HR Auto Response` (кастомная) или `YELLOW_STAR`
- **Message ID:** `{{ $('Gmail Trigger').item.json.id }}`

### 3.10 Wait Node — защита от манипуляций

**Нода:** `Wait`

**Проблема:** мгновенный ответ раскрывает факт автоматизации. Кандидаты могут перебирать варианты резюме, подгоняя их под систему.

**Решение:** добавить искусственную задержку перед отправкой ответа — от 30 минут до нескольких часов, имитируя работу живого HR-специалиста.

| Вариант | Реализация |
|---|---|
| Фиксированная | 30 минут |
| Случайная | `{{ Math.floor(Math.random() * 3 + 1) }}` часа |

## 4. Защита от дублирования кандидатов

**Задача:** не обрабатывать повторно одного и того же кандидата, если он уже есть в базе.

### Концепция реализации

1. **До сохранения** выполняется поиск в листе «Кандидаты» по полям `email` и/или `contact_phone`.
2. **Нода:** `Google Sheets → Get Many Rows` с фильтром по email.
3. **Нода If:** если запись найдена → пропустить сохранение, перейти сразу к шагу отправки (или отправить специальный ответ «мы уже знакомы с вашим профилем»).
4. **Альтернатива:** использовать `Code Node` с проверкой уникальности перед записью.

```
[Information Extractor]
      │
      ▼
[GSheets: Get Rows (filter by email)]
      │
      ▼
[If: кандидат уже существует?]
  ├── TRUE  → [пропустить онбординг / отправить спец. ответ]
  └── FALSE → [AI Agent Matching] → [GSheets: Append Row] → [Send Response]
```

## 5. Требования к инфраструктуре

### Внешние сервисы
| Сервис | Роль | Аутентификация |
|---|---|---|
| Gmail (Google API) | Триггер + отправка | Service Account (JSON key) |
| Google Sheets | База вакансий + кандидатов | Service Account |
| OpenAI API | GPT-4 для экстракции и мэтчинга | API Key |
| n8n | Оркестрация workflow | Self-hosted или Cloud |

### Google Cloud настройка
1. Создать проект в Google Cloud Console
2. Включить **Gmail API** и **Google Sheets API**
3. Создать **Service Account** с минимально необходимыми правами (принцип least privilege)
4. Скачать JSON-ключ
5. Дать сервисному аккаунту доступ к нужным документам Google Sheets

> ⚠️ **Принцип минимальных привилегий:** выдавать только те права, которые реально нужны. Утечка токена с широкими правами даёт злоумышленнику несанкционированный доступ к данным.

## 6. Структура n8n workflow (ноды по порядку)

```
1.  Gmail Trigger (On message received)
2.  Extract from PDF
3.  Information Extractor
      └─ OpenAI Chat Model
4.  [Блок защиты от дублей]
      └─ Google Sheets: Get Rows
      └─ If: дубль?
5.  AI Agent (Matching)
      ├─ OpenAI Chat Model (GPT-4, temp=0.3, JSON mode)
      └─ Google Sheets Tool (лист Вакансии)
6.  Structured Output Parser
7.  Google Sheets: Append Row (лист Кандидаты)
8.  If: score >= 60?
      ├─ TRUE  → Wait → Gmail: Send Invite → Gmail: Add Label
      └─ FALSE → Wait → Gmail: Send Reject → Gmail: Add Label
```

## 7. Риски и ограничения

| Риск | Описание | Митигация |
|---|---|---|
| Качество парсинга PDF | Нестандартные PDF могут плохо читаться | Добавить fallback на ручную обработку |
| Галлюцинации LLM | Модель может придумать несуществующие данные | Использовать Required-поля + валидация |
| Лимиты API | Gmail и OpenAI имеют квоты | Добавить Error Handler + retry |
| Дубли по разным email | Один человек, два email | Нечёткое сравнение по имени + телефону |
| Раскрытие автоматизации | Слишком быстрый ответ | Wait Node с рандомной задержкой |
| Утечка credentials | Широкие права сервисного аккаунта | Принцип least privilege + ротация ключей |

## 8. Метрики успеха

- **Точность экстракции данных** — % правильно извлечённых полей из резюме
- **Точность мэтчинга** — % корректных решений (приглашение/отказ) vs ручная проверка
- **Время обработки** — от получения письма до отправки ответа (без учёта Wait)
- **Процент дублей** — % задублированных кандидатов, остановленных на проверке
- **Доставляемость писем** — % успешно отправленных ответов
