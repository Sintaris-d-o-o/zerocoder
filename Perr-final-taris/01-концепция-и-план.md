# Выпускной проект — концепция и план

## Что делаем

Ничего нового не придумываем и не разрабатываем с нуля. Выпускной проект — это
**Taris**, наша действующая платформа (репозиторий `sintaris-pl`, версия 2026.9.95,
около 1 800 коммитов, работает на нескольких серверах). Наша работа — **честно и
понятно описать её по пяти разделам задания** и подтвердить каждое утверждение
реальным материалом: скриншотом, результатом теста, ссылкой на демо.

Задание формально предлагает «придумать проблему». У нас обратная ситуация: проблема
давно найдена, решение работает. Поэтому описание строится как история реального
продукта: с чего началось → какую проблему решаем → как устроено → как проверено →
как этим пользуются.

## Главное решение: как позиционировать Taris

Taris умеет очень много (голос, календарь, почта, контент, курсы, база знаний, CRM).
Для выпускного проекта нужна **одна понятная проблема и одна идея**, иначе описание
превратится в список функций. Варианты — все взяты из наших собственных документов:

| Вариант | Проблема | Для кого | Источник |
|---|---|---|---|
| **А. Экспертная платформа на базе знаний компании** (рекомендую) | Знания компании разбросаны по документам; ответы клиентам и сотрудникам, консультации и обучение отнимают время экспертов, а обычный чат-бот «придумывает» | малый и средний бизнес и эксперты, у которых ошибка дорога | демо-сценарий v2, одностраничник |
| Б. Платформа для экспертов и авторов курсов | Эксперт тратит время на администрирование курсов, учеников, оплат и напоминаний | коучи, консультанты, онлайн-школы | жизненный цикл, концепция Академии |
| В. Узкий кейс: ассистент по сертификации медизделий | Регуляторные вопросы (MDR/IVDR) требуют точных ответов со ссылками на статьи | производители и консультанты по медизделиям | демо `cert`, задание 10.7 |

**Почему А.** Она объединяет Б и В: база знаний — ядро, а курсы, консультации и
сертификация — примеры применения. Так позиционирует Taris наш собственный последний
демо-сценарий: «экспертная платформа — поддержка, консультации и обучение внутри базы
знаний компании». Это прямо попадает в тему задания («автоматизация бизнес-решений с
помощью ИИ») и в его пример («на основе базы знаний компании»). Для показа берём
сертификацию медизделий: там видно, что ответ опирается на документы, а не
выдумывается.

## Как каждый раздел задания закрывается тем, что уже есть

### 1. Проблема и идея

- **С чего началось.** Голосовой ассистент на Raspberry Pi (офлайн-распознавание и
  синтез речи) → Telegram-бот → веб-интерфейс → база знаний из документов → агенты
  автоматизации → платформа для экспертов. *Личную мотивацию («почему я за это взялся»)
  должны рассказать вы — я напишу черновик, вы поправите.*
- **Проблема, решение, идея** — по варианту А, в формате примера из задания.
- **Для кого** — сегменты и первый пилотный сегмент из документа о жизненном цикле.

### 2. Инструменты и технологии

| Что просит задание | Что есть в Taris |
|---|---|
| Python | весь бэкенд: FastAPI (веб), pyTelegramBotAPI (бот), обработка документов |
| Нейросети и API | OpenAI, YandexGPT, Gemini, Claude, OpenRouter; переключение моделей из админ-панели без остановки |
| Зерокод | **n8n** вместо Make/Zapier/Albato: рассылки, синхронизация с CRM, приём событий. Объясним, почему n8n (свой сервер, данные у нас) |
| Комбинация Python + зерокод | логика и нейросети — в Python, внешние сервисы — через n8n, ровно как предлагает задание |
| Облачное и локальное развёртывание моделей | Ollama и llama.cpp на своём сервере, резервная локальная модель; VPS с Docker |
| Дообучение | эксперименты из заданий 8.1–8.3 и профили настройки моделей в Taris |
| LangChain | в ядре Taris **не используется** — поиск по базе знаний написан свой (полнотекстовый + векторный + объединение рангов). Честно объясним почему: прозрачность и контроль качества. LangChain разбирали в задании 6.2 |

### 3. Основные функции

Четыре функции из задания — в Taris все четыре:

- **Взаимодействие с пользователем** — Telegram-бот, веб-приложение, голос; 4 языка.
- **Работа с API** — нейросети, Telegram, VK, Google, почта, n8n, собственный REST API.
- **Генерация текста и данных** — ответы ассистента, посты и контент-план с картинкой,
  сводки почты, разбор календаря на естественном языке.
- **Интеграция с базой знаний** — загрузка PDF/Word, поиск, ответ со ссылками на
  источник, отказ, если ответа в документах нет.

### 4. Тестирование

Это самый сильный раздел — у Taris настоящая система проверок:

- 837 зарегистрированных тестов; на рабочем сервере прогон 1 881 проверки и 132
  браузерных сценария (Playwright) — это цифры августа 2026 (версия 2026.8.8), перед
  сдачей прогоним заново и возьмём свежие;
- журнал ошибок: каждая найденная в работе ошибка — причина, почему тесты её
  пропустили, что теперь не даёт ей повториться;
- замеры качества ответов по базе знаний, сравнение моделей, скорость.

Возьмём 2–3 конкретные истории «нашли ошибку → исправили → защитили тестом» — они
лучше всего отвечают на пункт «устрани ошибки и оптимизируй».

### 5. Формат взаимодействия

Задание просит выбрать один формат — у нас их несколько, и это плюс: **Telegram-бот +
веб-приложение (можно установить на телефон) + голос + REST API для интеграций**.

## План работы

1. Сохранить задание и этот план, commit, push. ✅ (этот шаг)
2. **Вы подтверждаете** позиционирование и отвечаете на вопросы ниже.
3. Пишу `02-описание-проекта.md` — главный документ по пяти разделам, простым языком.

## План проверки (самого описания)

- Каждая цифра и каждая функция в описании имеет источник: файл, тест или скриншот.
- В описании нет того, чего нет в коде (такую ошибку мы уже ловили в задании 7.4).
- Нет секретов, адресов серверов, паролей, имён и данных клиентов.
