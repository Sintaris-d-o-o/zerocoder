# Новый n8n на SintAItion: что есть, что предлагаю, что делать не буду

Документ для согласования. Разработку не начинаю до вашего «да».

---

## 1. Ответ на ваш вопрос: Taris пользуется своим n8n, не с VPS

В настройках SuperTaris записано:

```
N8N_URL=http://127.0.0.1:5678
N8N_CAMPAIGN_SELECT_WH=http://127.0.0.1:5678/webhook/taris-content-generate
N8N_CAMPAIGN_SEND_WH=http://127.0.0.1:5678/webhook/taris-campaign-send
```

Адрес локальный, значит обращения идут к n8n на той же машине. С VPS Taris по n8n не ходит.

## 2. Что уже развёрнуто на SintAItion

| Что | Где | Хранилище | Кто пользуется |
|---|---|---|---|
| n8n основной | порт 5678 | SQLite в домашней папке | SuperTaris: рассылки, генерация контента |
| n8n-cert | порт 5680, отдельный том | SQLite в томе Docker | сертификатный контур (задания 7.1, N3) |

Обе установки — образ `n8nio/n8n:latest`, версия **2.17.7**. Docker 29.1.3, PostgreSQL 16.15,
на диске свободно 704 ГБ.

То есть **n8n там уже есть, и даже два**. Разворачивать «потому что нет» не нужно, но есть
причина развернуть третий — о ней ниже.

## 3. Две находки в текущей конфигурации

Пока смотрел настройки, нашлось два расхождения. К заданию они отношения не имеют, но чинить
их полезно.

**Первое: переменная кампаний указывает на вебхук генерации контента.**

```
N8N_CAMPAIGN_SELECT_WH=http://127.0.0.1:5678/webhook/taris-content-generate
```

Судя по имени, там должен быть `taris-campaign-select`. Похоже на опечатку при настройке:
отбор получателей для рассылки дёргает цепочку, которая пишет посты.

**Второе: контент-агент не пользуется n8n вообще.** Переменная `N8N_CONTENT_GENERATE_WH` в
настройках не задана. Значит, при генерации поста агент каждый раз уходит на запасной путь —
локальную модель. А написанная и отлаженная цепочка `Taris - Content Generate` с gpt-4o-mini
просто не вызывается.

Это важно для оценки скорости: локальная модель на этой машине отвечает заметно медленнее
облачной, и в документации проекта записан замер, где разница составила два порядка.

## 4. Что предлагаю сделать

Три части. Первая — инфраструктура, вторая — польза для продукта, третья — само задание.
Границу между второй и третьей провожу намеренно: в Taris попадёт только то, что не спорит
с его устройством.

### Часть А. Новый n8n в Docker на PostgreSQL

Поднимаю третий экземпляр, отдельный от двух работающих:

| Параметр | Значение | Почему так |
|---|---|---|
| Образ | `n8nio/n8n` свежей версии | сейчас стоит 2.17.7, возьму актуальную на день установки |
| Порт | 5681 | 5678 и 5680 заняты |
| Хранилище | **PostgreSQL 16**, новая база `n8n_lab`, отдельная роль | у обоих работающих экземпляров SQLite |
| Данные | том Docker, как у n8n-cert | не мусорим в домашней папке |
| Автозапуск | `restart: unless-stopped` | переживёт перезагрузку |
| Доступ | только с этой машины | наружу не выставляю |

**Зачем PostgreSQL, а не SQLite.** Сам n8n рекомендует его для рабочих установок: SQLite
упирается в блокировки при одновременных запусках и хуже переживает аварийное выключение.
На этой машине PostgreSQL уже работает и обслуживает базы Taris, так что новая база — это
несколько команд, а не новый сервис.

**Зачем третий экземпляр, а не использовать существующий.** Рабочий n8n обслуживает
рассылки SuperTaris. Учебные опыты с автопубликацией в канал туда лезть не должны: ошибка в
чужой цепочке — это письма живым людям. Новый экземпляр изолирует эксперименты и заодно
становится площадкой, где можно проверить переезд на PostgreSQL, прежде чем трогать рабочий.

### Часть Б. Польза для Taris

Вот что из этого стоит взять в продукт. Всё опциональное, всё выключается настройкой.

**1. Подключить контент-агента к n8n, как и задумано.** Цепочка написана, но не вызывается.
Ставим `N8N_CONTENT_GENERATE_WH` на новый экземпляр и сравниваем на одинаковых темах: время
ответа и качество текста против локальной модели. Если облачная заметно быстрее, у вас
появляется настройка «где генерировать», а не жёсткий выбор.

**2. Починить переменную кампаний.** Одна строка, но сейчас рассылка ходит не туда.

**3. Перенести n8n на PostgreSQL — сначала на новом экземпляре.** Если приживётся, тем же
способом переводится рабочий. Это снимает риск блокировок SQLite, о который n8n спотыкается
при параллельных запусках.

**4. Описать n8n как часть платформы.** Сейчас в реестре машин n8n не значится: в разделе
служб перечислены только службы Taris. Добавить его туда — значит получить n8n в том же
списке, что и остальное, вместе с резервным копированием базы.

### Часть В. Задание урока — отдельно от продукта

Учебная цепочка живёт в новом экземпляре и в Taris не попадает:

```
Вебхук POST (тема) → подготовка промпта → gpt-4o-mini → разбор ответа → HTTP-запрос
к Telegram API → ответ вызывающему
```

Цепочка и скрипт уже написаны и лежат в папке задания: [workflow.json](workflow.json),
[main.py](main.py), 17 тестов проходят.

## 5. Чего делать не буду и почему

**Не буду встраивать автопубликацию в Taris.** Задание требует, чтобы внешний вызов публиковал
пост в канал без участия человека. В Taris публикация намеренно устроена иначе: пользователь
выбирает канал и отдельно подтверждает отправку, а расписания и отложенной публикации нет
вовсе — это проверено поиском по всему коду.

Причина видна из устройства продукта: пост выходит от имени бренда. Поэтому автопубликация
останется учебной цепочкой в отдельном экземпляре n8n.

**Не буду трогать рабочие экземпляры n8n.** Ни их цепочки, ни их данные.

**Не буду выставлять новый n8n наружу.** Доступ только с самой машины.

**Не буду менять настройки SuperTaris без отдельного согласия.** Две находки из раздела 3 —
это предложение, а не план. Скажете чинить — починю, но отдельным шагом.

## 6. Риски и как их закрываю

| Риск | Что делаю |
|---|---|
| Новый контейнер займёт порт работающего | ставлю 5681, проверяю занятость до запуска |
| Установка n8n сломает что-то на машине | отдельный контейнер, отдельный том, отдельная база; рабочие не трогаю |
| Новая база в PostgreSQL помешает базам Taris | отдельная роль с правами только на свою базу |
| Память: веб-служба уже близко к пределу | n8n ест немного, но проверю потребление после запуска и покажу цифры |
| Ключ OpenAI попадёт в цепочку | ключи только в переменных окружения контейнера, в файле цепочки их нет — это проверяется тестом |
| Токен бота утечёт в репозиторий | тот же приём; в файл цепочки уходит `$env.TELEGRAM_BOT_TOKEN` |
