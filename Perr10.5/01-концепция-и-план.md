# Задание 10.5 — концепция и план

## Что просят

Собрать в n8n автопостинг в Telegram:

1. Развернуть n8n в Docker, убедиться, что он доступен.
2. Цепочка: **вебхук (POST) → модель → HTTP-запрос к Telegram API**. Тема поста приходит
   в теле запроса параметром `topic`, в узле модели используется переменная из запроса.
3. Бот через BotFather, канал, бот администратором канала, отправка через `chat_id`, `text`,
   `parse_mode=HTML`.
4. Скрипт на Python шлёт POST на вебхук, проверяем код ответа 200 и публикацию в канале.

Отчёт: скриншоты контейнера, схемы цепочки, журнала выполнений со статусом успеха,
опубликованного поста и файл скрипта.

## Что уже есть в наших проектах

Тема урока — генерация постов для Telegram — у нас закрыта дважды, причём обе реализации
живые.

### 1. Контент-Стратег, `@ContentStrategyAssist_bot`

Бот на собственном движке (`universal-tgrm-bot`, ветка `gpt-tgrm-bot`). Устройство необычное:
код — универсальный сценарный движок, а сам бот это **один файл настроек** на 83 экрана и 45
переменных. Новый инструмент добавляется правкой JSON и командой перезагрузки конфигурации,
без перезапуска. На том же движке работают ещё пять ботов, каждый отличается только своим
сценарием, базой и токеном.

| | |
|---|---|
| Движок | 10 файлов Python, 3 753 строки |
| Документация | 4 491 строка |
| Сценарий бота | 83 узла, 78 кнопок, 10 обращений к модели |
| Инструменты | контент-план на 7 дней, интерактивы, темы эфиров, посты |
| Модель | gpt-4o |
| Живые данные | 40 пользователей, 332 диалога с моделью, 1 487 действий, 380 тысяч входных токенов |
| Среднее время ответа | 14 секунд |
| Монетизация | коды активации с квотами |

Результат отдаётся пользователю в чат. Публикации в канал нет.

### 2. Агент «Контент-стратег» в платформе Taris

Один из девяти агентов платформы, работает и в браузере, и в Telegram.

| | |
|---|---|
| Код агента | около 3 550 строк: сам агент, публикация в ВКонтакте, генерация картинок, хранилище |
| Маршруты в вебе | 15 из 36 агентских |
| Путь | три вопроса → план на 7 постов → выбор поста → текст → картинка → публикация |
| Публикация | Telegram и ВКонтакте, напрямую через их API |
| Картинки | отдельная модель, файл хранится локально |
| Учёт | таблица постов и временной ряд метрик, вовлечённость считается, а не хранится |

**И главное для этого задания: генерация текста уже идёт через n8n.** В платформе есть
рабочий процесс `Taris - Content Generate`:

```
Webhook (POST, taris-content-generate) → Prepare Prompt (код) → OpenAI (gpt-4o-mini)
  → Parse Response (код) → Respond to Webhook
```

Это первые два звена из задания, уже работающие в продакшне. Рядом лежит второй процесс
`Taris - Content Publish` с узлом Telegram, где адрес канала и текст берутся из входного
запроса, — но он **не подключён**: переменная для него объявлена, а вызова в коде нет.

## Чего в продукте нет намеренно

Публикация в Taris происходит только после того, как человек выберет канал и подтвердит
отправку. Расписания, отложенной публикации и входящего вызова, который запускал бы
генерацию, нет вовсе — это проверено поиском по всему коду.

Причина понятна: пост выходит от имени бренда, и последнее слово оставлено человеку.

**Задание просит ровно тот контур, который в продукте сознательно разомкнут** — чтобы внешний
вызов запускал генерацию и публикацию без участия человека.

## Что делаем

Собираем цепочку, которую требует урок, и показываем её рядом с двумя существующими
реализациями. Получается разбор одной задачи на трёх уровнях автоматизации:

| Уровень | Кто запускает | Что на выходе | Где живёт |
|---|---|---|---|
| Контент-Стратег | человек в диалоге | пост в чат пользователю | свой движок, 332 живых диалога |
| Агент Taris | человек кнопкой | пост с картинкой в канал после подтверждения | платформа, два интерфейса |
| **Цепочка задания** | внешний вызов | пост в канал без человека | n8n |

Практическая часть переиспользует наработки: узлы подготовки промпта и разбора ответа берутся
из работающего процесса, добавляется публикация.

## План работ

1. `workflow.json` — цепочка для импорта в n8n: вебхук → подготовка промпта → модель →
   разбор → публикация в Telegram → ответ вызывающему.
2. `main.py` — скрипт, который шлёт POST с темой и печатает результат.
3. Импорт цепочки в n8n, подключение ключей, тестовый прогон.
4. Скриншоты: контейнер, схема, журнал выполнений, пост в канале.
5. `результаты.md` — сверка с заданием и сравнение трёх уровней автоматизации.
