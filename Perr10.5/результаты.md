# Задание 10.5 — что сделано и что получилось

## Коротко

Собран автопостинг в Telegram: внешний POST-запрос с темой → генерация текста моделью →
публикация в канал. Всё работает на новом n8n, который развёрнут на домашнем сервере
SintAItion и открыт наружу по адресу **https://sintaition.sintaris.net**.

Проверка «по-настоящему»: скрипт запущен с чужой машины (VPS в Германии), запрос прошёл
через интернет, ответ пришёл за **3,3 секунды**, пост появился в канале.

Публикации: <https://t.me/bussness_automation/2> и <https://t.me/bussness_automation/4>.

## Что именно построено

### 1. n8n в Docker

| | |
|---|---|
| Версия | 2.39.8 — самая свежая на день сдачи |
| Контейнер | `n8n-new`, перезапуск автоматический |
| Где | сервер SintAItion, рядом с certtaris |
| База данных | PostgreSQL (своя база `n8n`), а не файл SQLite |
| Память | 368 МБ |
| Порт | 5681 |

Почему не 5678, как в уроке: этот порт на машине уже занят старым n8n. Новый поставлен
рядом, на свободный порт, чтобы ничего не ломать. Ещё один порт пришлось сменить —
внутренний «брокер задач» тоже конфликтовал со старым экземпляром.

Почему PostgreSQL, а не файл: файл SQLite — это один файл, который легко потерять и
трудно нормально резервировать на ходу. База, которая уже работает на этой машине для
других сервисов, бэкапится вместе со всем остальным.

Контейнер пересоздаётся скриптом `run.sh` (лежит на сервере в `~/n8n-new/`). Версия
образа в нём прописана явно — обновление становится осознанным решением, а не
случайностью при очередном перезапуске. Пароли и ключи скрипт читает из `.env` рядом,
в самом скрипте их нет.

### 2. Внешний адрес

Задание требует адрес вида `http://localhost:5678`. Этого мало: вебхук, доступный только
с самой машины, бесполезен — внешняя система на него не постучится. Поэтому сделан
настоящий публичный вход:

```
браузер или внешний скрипт
      ↓  https://sintaition.sintaris.net
VPS в Германии: nginx + сертификат Let's Encrypt
      ↓  обратный SSH-туннель (порт 8093)
SintAItion: n8n на порту 5681
```

Туннель держит отдельная служба `taris-tunnel-n8n.service`. Сделана отдельной намеренно:
существующий туннель обслуживает supertaris и certtaris, и его перезапуск оборвал бы
доступ к ним.

Сертификат выпущен автоматически и продлевается сам, действует до 19 декабря 2026.

### 3. Сама цепочка

```
Webhook (POST /zerocoder-autopost)
  → Prepare Prompt      — собирает задание для модели из параметра topic
  → AI Message a model  — gpt-4o-mini
  → Parse Response      — достаёт текст из ответа, режет до 4000 знаков
  → HTTP Request        — api.telegram.org/bot<токен>/sendMessage
  → Build Result        — собирает ответ: ссылка на пост, номер сообщения
  → Respond to Webhook  — отдаёт результат тому, кто вызвал
```

Два узла добавлены сверх минимума из задания, и оба не для красоты:

- **Parse Response** режет текст до 4000 знаков. Telegram не принимает сообщения длиннее
  4096 — без обрезки публикация падала бы на длинных постах.
- **Build Result** возвращает вызывающему ссылку на пост. Без него ответ 200 означал бы
  только «n8n получил запрос», а не «пост опубликован».

Токен бота не лежит в цепочке: узел берёт его из переменной окружения контейнера. Файл
`workflow.json` можно открыто хранить в репозитории — секретов в нём нет.

### 5. Скрипт проверки

`main.py` шлёт POST с темой и печатает результат. Запуск с VPS:

```
Код ответа: 200 ✔ успех
{
  "ok": true, "published": true,
  "message_id": 4,
  "url": "https://t.me/bussness_automation/4"
}
Пост опубликован, идентификатор сообщения 4
```

Рядом лежат ещё два скрипта, которых задание не требовало, но без них работа была бы
ручной:

- `deploy_workflow.py` — загружает цепочку в n8n и включает её через его же API.
  Заодно заводит ключ OpenAI. Повторный запуск обновляет цепочку, а не плодит копии.
- `last_run.py` — показывает, что произошло в последнем запуске: какой узел что отдал и
  где упало. Полезен тем, что n8n хранит журнал в сжатом формате, который обычным
  способом не прочитать.

## Что пошло не так и чему научило

### Узел модели оказался не тем

В n8n два разных узла с почти одинаковым названием. Старый `n8n-nodes-base.openAi`
импортируется без единой ошибки и выглядит рабочим — но обращается к устаревшему способу
общения с моделью. Системная роль и тема игнорируются, а на выходе приходит посторонний
текст: в нашем запуске модель вернула обрывок рекламы интернет-магазина вместо поста
про сертификаты.

Операция «Message a Model» из урока живёт в другом узле — `@n8n/n8n-nodes-langchain.openAi`.
После замены всё заработало с первого раза.

Отдельная тонкость: у этого узла по умолчанию включено «упрощение ответа», и тогда
структуры `choices` в ответе просто нет — обращаться по индексу `[0]`, как требует
задание, становится не к чему. Упрощение выключено намеренно.

Вывод, который стоит запомнить: **то, что цепочка импортировалась без ошибок, ещё не
значит, что узел тот самый**. Проверять надо по результату первого запуска, а не по
зелёным галочкам импорта.

### Версии узлов надо сверять до развёртывания, а не после

Перед установкой проверено, какие версии узлов понимает установленный n8n — прямо внутри
контейнера. Так нашлась собственная ошибка: в цепочке стояла версия узла, которой у
выбранного типа не существует. Это тот случай, когда пятиминутная проверка экономит
полчаса разбирательств на живом сервере.

Проверка теперь закреплена тестом: `tests/test_main.py` сверяет версии узлов в
`workflow.json` со списком поддерживаемых. Всего в файле 20 тестов, все проходят.

### Идентификатор канала в настройках записан не в той форме

В `config/hosts/cert.env` идентификатор канала лежит без приставки `-100`
(например `3863639639` вместо `-1003863639639`). Telegram на такой идентификатор отвечает
«chat not found». В настройках n8n значение исправлено, **в самом cert.env оставлено как
есть** — это файл продукта, менять его без вашего решения не стал. Если публикатор Taris
пойдёт в канал по этому значению напрямую, он упадёт.

## Состояние сервера после работы

Все изменения записаны в журнал администрирования (`sintaris-srv`, Session 28):
7 изменений, 3 находки, 4 проверки.

**Осталось решить:** старый n8n на SintAItion (порт 5678) с момента установки не выполнил
ни одного рабочего процесса и занимает около 570 МБ памяти. После переключения certtaris
на новый экземпляр его можно выключить. Рабочий `n8n-cert` (порт 5680, 1296 выполнений за
две недели) не тронут и работает как раньше.
